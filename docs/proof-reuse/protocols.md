# Protocol, attestation and transparency proof sources

This research inventory maps external proof artifacts to the current [requirements register](../requirements-register.md), [crown jewels](../crown-jewels.md) and [implementation plan](../implementation-checklist.md). It includes strong exemplars, partial developments and unsuitable candidates so that a familiar project name is not mistaken for an applicable theorem. Source inspection is dated 2026-09-10. No external prover is replayed for this inventory, and no imported theorem discharges a platform requirement. Immutable revisions identify inspected source, not a successful local build.

The strongest immediate starting points in the platform's language are Cerisier's local-attestation contract and Cryptis's resource-aware authentication proofs. The radio artifacts supply unusually concrete symbolic specifications, attack witnesses and patched variants. They still require the formal-to-formal transcription and Lustre refinement prescribed by R-12-043b through R-12-043f. Q22b and Q22c retain ownership of selecting the actual witness and attestation-session constructions. No source below is an exact drop-in for the project's current types and assumptions.

## Cerisier: local attestation and capability authority

- **Authorship and standing:** June Rousseau, Denis Carnier, Thomas Van Strydonck, Steven Keuchel, Dominique Devriese and Lars Birkedal, [Cerisier: A Program Logic for Attestation in a Capability Machine](https://arxiv.org/abs/2604.13638), PLDI 2026. The artifact supplies a paper-to-mechanization map.
- **Artifact:** existing gitlink `upstream/cerisier`, revision `57ed584ae17eed308ae0fa554cf0dde9843112c1`; [`theories/logrel/fundamental.v`](https://github.com/logsem/cerisier/blob/57ed584ae17eed308ae0fa554cf0dde9843112c1/theories/logrel/fundamental.v), theorem `cerisier_universal_contract`. [`opam`](https://github.com/logsem/cerisier/blob/57ed584ae17eed308ae0fa554cf0dde9843112c1/opam) pins Coq 8.18.0, Iris 4.1.0 and stdpp 1.9.0; the upstream focused replay is `make fundamental`.
- **License:** [`LICENSE`](https://github.com/logsem/cerisier/blob/57ed584ae17eed308ae0fa554cf0dde9843112c1/LICENSE) grants BSD-3-Clause terms outside `extra/`; retain notices and disclaimer, with no endorsement implied. [THIRD-PARTY.md](../../THIRD-PARTY.md) separately resolves the documentation-theme carve-out.
- **Fit and gap:** foundation for `CJ-CERISE`, the R-05-160 attestation/capability seam and Q22c. This is a local CHERI-TrEE enclave model, not the selected RV64 Sail semantics or a remote TLS session. Image binding, initialization refinement, appraisal policy, freshness and authenticated session-key ownership remain to be modeled and connected under R-12-015c. **Disposition: preferred same-language foundation, already pinned; no import needed.**

## Cryptis: symbolic authentication inside Iris

- **Authorship and standing:** Arthur Azevedo de Amorim, Amal Ahmed and Marco Gaboardi, [Cryptis: Cryptographic Reasoning in Separation Logic](https://popl26.sigplan.org/details/POPL-2026-popl-research-papers/90/Cryptis-Cryptographic-Reasoning-in-Separation-Logic), POPL 2026.
- **Artifact:** revision `74982c92967a18793ad850be6b13a6cad5e4f818`; [`examples/nsl_auth.v`](https://github.com/arthuraa/cryptis/blob/74982c92967a18793ad850be6b13a6cad5e4f818/examples/nsl_auth.v), `wp_init`, `wp_resp`, `wp_game` and `nsl_secure`. The [README](https://github.com/arthuraa/cryptis/blob/74982c92967a18793ad850be6b13a6cad5e4f818/README.md) gives Rocq 9.1.1, Iris/HeapLang 4.5.0 and MathComp ssreflect 2.5.0, with `make` as replay.
- **License:** [`LICENSE`](https://github.com/arthuraa/cryptis/blob/74982c92967a18793ad850be6b13a6cad5e4f818/LICENSE), MIT, copyright 2021 Arthur Azevedo de Amorim; copyright and permission notice must accompany substantial copies.
- **Fit and gap:** useful to Q22c, R-12-015a and R-12-015c for connecting authentication to ownership of resources. NSL, DH/ISO, secure connections, RPC and authenticated store examples show compositional reasoning in the symbolic model. HeapLang is not this platform's executable semantics; ideal cryptography and compromise conditions must be retained, and computational soundness is not supplied. The README explicitly labels its TLS 1.3 and OPAQUE cases partial. **Disposition: preferred proof pattern, with a Rocq/Iris version bridge and target model still owed.**

## Copland: layered attestation orchestration and manifests

- **Authorship and standing:** John D. Ramsdell and Paul D. Rowe, [Copland Attestation Terms: Semantics and Coq Proofs](https://ku-sldg.github.io/copland/resources/coplandcoq/index.html); Adam Petz and Perry Alexander, [An Infrastructure for Faithful Execution of Remote Attestation Protocols](https://arxiv.org/abs/2012.10511). These are related proof developments rather than a single unchanged artifact.
- **Artifact:** [`ku-sldg/copland-avm`](https://github.com/ku-sldg/copland-avm/tree/6c9ee8ed9a972c7d0a6c901648b7a9b312e0e26b), revision `6c9ee8ed9a972c7d0a6c901648b7a9b312e0e26b`; `src/ManCompSoundness.v` contains `manifest_generator_compiler_soundness_distributed_multiterm`. The current README names a Coq fork on `cakeml-extraction`, without a complete immutable toolchain pin. Its historical `CvmSemantics.v` description is not an extant file at this revision and must not be used as an exact current locator.
- **License:** [`src/license.txt`](https://github.com/ku-sldg/copland-avm/blob/6c9ee8ed9a972c7d0a6c901648b7a9b312e0e26b/src/license.txt) carries MITRE's 2018 three-clause redistribution permission and government-contract notice. Applicability to subsequently added files requires per-file review; this is not blanket clearance inferred from ancestry.
- **Fit and gap:** Q22c, `CJ-ATTEST`, R-12-014 and R-12-015c can reuse the event/evidence semantics and orchestration refinement approach. The current development explicitly abstracts some identifiers and cryptographic parameters; manifest support is not a computational session-binding theorem. **Disposition: substantive same-language research source; resolve assumptions, source lineage and toolchain before reuse.**

## VRASED and PURE: attestation atomicity and lifecycle, with known limitations

- **Authorship and standing:** Ivan De Oliveira Nunes, Karim Eldefrawy, Norrathep Rattanavipanon, Michael Steiner and Gene Tsudik, [VRASED](https://www.usenix.org/conference/usenixsecurity19/presentation/de-oliveira-nunes), USENIX Security 2019. Nunes, Eldefrawy, Rattanavipanon and Tsudik's [PURE](https://sprout.ics.uci.edu/projects/attestation/papers/pure.pdf), ICCAD 2019, extends that architecture to update, reset and erasure.
- **Artifact:** VRASED revision `62ceb1f60b0859f9017c6a9fec07a5022226da33`; [`verification_specs/soundness_and_security_proofs`](https://github.com/sprout-uci/vrased/tree/62ceb1f60b0859f9017c6a9fec07a5022226da33/verification_specs/soundness_and_security_proofs) includes `proof_theorem1.ltl`, `proof_theorem2_1.ltl` and `proof_theorem2_2.ltl`, using Spot 2.0. Hardware subproperties use NuSMV. PURE's `pure` branch is `e454fe70b9e42e31e8fdc8ba07c5ecbc115f4add`, with `verification_specs/pure_PoR_proofs` as its reset-proof entry point.
- **License:** both branches' own [`LICENSE`](https://github.com/sprout-uci/vrased/blob/e454fe70b9e42e31e8fdc8ba07c5ecbc115f4add/LICENSE) contains GPLv3; constituent HACL and OpenMSP430 materials require their own review. No source is conveyed here.
- **Fit and gap:** R-09-003, R-09-008, R-09-019 and the M3 RoT work benefit from the decomposition into atomicity, key access and erasure obligations. This MSP430 design is not the platform's RoT. More seriously, Bognar, Van Bulck and Piessens's [Mind the Gap artifact](https://github.com/martonbognar/vrased-gap) demonstrates implementation/model mismatches, omitted attacker capabilities and missing core assumptions while the original proof strategy passes. The authors caution that derivatives may share those gaps. **Disposition: useful specification and negative-review evidence, not an accepted security foundation.**

## miTLS: computational record-layer security

- **Authorship and standing:** Karthikeyan Bhargavan, Antoine Delignat-Lavaud, Cédric Fournet, Markulf Kohlweiss, Jianyang Pan, Jonathan Protzenko, Aseem Rastogi, Nikhil Swamy, Santiago Zanella-Béguelin and Jean Karim Zinzindohoué, [Implementing and Proving the TLS 1.3 Record Layer](https://antoine.delignat-lavaud.fr/doc/oakland17.pdf), IEEE S&P 2017.
- **Artifact:** [`project-everest/mitls-fstar`](https://github.com/project-everest/mitls-fstar/tree/9a75fa8c46e50897b1f43002885d25a34dfa929a), revision `9a75fa8c46e50897b1f43002885d25a34dfa929a`; `src/tls/MiTLS.AEAD.Pkg.fsti` specifies the AEAD invariant and `encrypt`, alongside `MiTLS.Record.fst` and `.fsti`. The README describes F* 0.9 lineage and `src/tls`'s `make all-ver`; a historical paper-matching toolchain/artifact correspondence is not established by this source inspection.
- **License:** [`LICENSE`](https://github.com/project-everest/mitls-fstar/blob/9a75fa8c46e50897b1f43002885d25a34dfa929a/LICENSE), Apache-2.0, copyright 2015 INRIA and Microsoft Corporation.
- **Fit and gap:** R-12-031, R-12-032 and R-05-078. The paper gives computational reductions from record-layer guarantees to cipher assumptions and concrete usage bounds. It does not turn the current hybrid PQ handshake, credential service or CHERI compilation path into verified code. F*/Z3 is outside the platform proof kernel, and draft-era TLS coverage must be reconciled with the selected wire profile. **Disposition: strong computational and implementation exemplar; substantial port and profile review.**

## Bertie: implementation-derived symbolic TLS analysis

- **Authorship and standing:** the [project README](https://github.com/cryspen/bertie/blob/a1f27d62f419511e0212da84270b078805e60bae/README.md) credits initial authorship to Karthikeyan Bhargavan at Inria and subsequent Cryspen stewardship. The primary [hax protocol-verification account](https://cryspen.com/post/hax-pv/) documents extraction from Rust. A publication's complete author list is not established here, so no paper acceptance is inferred.
- **Artifact:** revision `a1f27d62f419511e0212da84270b078805e60bae`; [`proofs/proverif/extraction/analysis.pv`](https://github.com/cryspen/bertie/blob/a1f27d62f419511e0212da84270b078805e60bae/proofs/proverif/extraction/analysis.pv), `ClientFinishedHandshake`/`ServerFinishedHandshake` correspondence queries and compromised-certificate-key cases. [`PROOFS.md`](https://github.com/cryspen/bertie/blob/a1f27d62f419511e0212da84270b078805e60bae/PROOFS.md) gives ProVerif 2.05, F* 2025.03.25 and `hax-driver.py typecheck-proverif`.
- **License:** [`LICENSE`](https://github.com/cryspen/bertie/blob/a1f27d62f419511e0212da84270b078805e60bae/LICENSE), Apache-2.0; retain applicable notices and mark adaptations.
- **Fit and gap:** directly matches the lineage named by R-12-032. Queries intentionally expected to fail witness handshake reachability and lack of authentication after signing-key compromise. Generated symbolic analysis and F* panic-freedom are distinct claims. Handwritten abstractions, extraction fidelity, the selected hybrid group and crypto-core integration remain obligations. **Disposition: preferred implementation-aligned TLS candidate, not a locally replayed platform theorem.**

- **Fit and gap:** R-06-003 and R-12-032 benefit from the package decomposition, but language compatibility alone is insufficient. ## 5G AKA: authentication, agreement and privacy variants

- **Authorship and standing:** David Basin, Jannik Dreier, Lucca Hirschi, Saša Radomirović, Ralf Sasse and Vincent Stettler, [A Formal Analysis of 5G Authentication](https://people.inf.ethz.ch/rsasse/pub/5G-CCS18.pdf), CCS 2018.
- **Artifact:** Tamarin repository revision `0f62d217ab84abc9c1d3c396034d3b67762c3411`, [`examples/ccs18-5G`](https://github.com/tamarin-prover/tamarin-prover/tree/0f62d217ab84abc9c1d3c396034d3b67762c3411/examples/ccs18-5G). `5G-AKA-bindingChannel/5G_AKA.spthy` includes `injectiveagreement_ue_seaf_kseaf_keyConf_noKeyRev_noChanRev`; separate nonbinding-channel and untraceability models retain attacks. README replay uses Tamarin 1.4.0 plus supplied oracles; current source includes later tactics, so historical-version replay requires the paper-era revision.
- **License:** the repository's [`LICENSE`](https://github.com/tamarin-prover/tamarin-prover/blob/0f62d217ab84abc9c1d3c396034d3b67762c3411/LICENSE) is GPLv3. Do not infer a separate permissive license for example models.
- **Fit and gap:** R-12-041 and R-12-043e, the NAS reference-model work. The models target TS 33.501 v15.0.0 and distinguish channel-binding, key-confirmation and compromise assumptions. A failed property is not a proven guarantee; passive privacy does not establish active unlinkability. This is neither all NAS nor a Lustre implementation proof. **Disposition: preferred symbolic lineage; select exact variant, pin and transcribe.**

The sibling N2 model covers another intra-5G handover path. README reports Tamarin 1.5.1, revision `57056945acf0d3aa91784a4cf93e37270cc97dc6`, plus oracles; replay must account for later source changes.

This does not cover every RRC state, timer or procedure. **Disposition: strong analyzed-model starting point, with unmodeled RRC procedures explicitly outstanding.**

## WPA2: four-way handshake, counters and key reinstallation

- **Authorship and standing:** Cas Cremers, Benjamin Kiesl and Niklas Medinger, [A Formal Analysis of IEEE 802.11's WPA2](https://www.usenix.org/conference/usenixsecurity20/presentation/cremers), USENIX Security 2020.

Exact entry points are `model/wpa2_four_way_handshake.m4`, `model/encryption_layer.m4i`, and `automatic_proofs/authenticator_ptk_is_secret.spthy`. The latter proves the named lemma for the patched model; separate files preserve unpatched KRACK traces. Upstream specifies Tamarin 1.4.1 and GNU M4, with manual and automatic proof directories.
- **License:** the inspected release page does not state a source redistribution license. Public download and a freely readable paper do not establish permission to vendor. A license in the archive still requires inspection before incorporation.
- **Fit and gap:** R-12-043e's MLME lineage, particularly counter monotonicity and key installation. The model covers interactions among four-way/group-key handshakes, WNM sleep and encryption. It is WPA2 evidence, not a WPA3 SAE proof or complete MLME implementation refinement. **Disposition: strong proof exemplar; source-license clearance and WPA3 composition required.**

Keep original-standard, patched and concurrent-session models separate; the archive includes queries marked false, and the paper distinguishes proofs from unresolved automatic analyses. ## Transparency protocols: Merkle proofs and observable certificates

- **Authorship and standing:** Vincent Cheval, José Moreira and Mark Ryan, [Automatic Verification of Transparency Protocols](https://www.cs.ox.ac.uk/people/vincent.cheval/publis/CMR-EuroSnP23.pdf), EuroS&P 2023.
- **Artifact:** the paper's [source archive](https://www.dropbox.com/sh/gbn5dy0amz1106f/AACbcILzg8o1Bhf5D3nMFa2Wa?dl=1) contains `models/certificate_transparency.pv`, `models/interface.pvl`, and `models/MerkleTree/merkle_proof_1-4-5-6.pv` plus companion proofs. `verify_pp` and `verify_pe` expose inclusion and extension predicates. The bundled prover is `proverifEuroSnP23`, an extended ProVerif source distribution rather than an established current-release replay.
- **License:** `proverifEuroSnP23/LICENSE` contains GPLv2. No separate model license is identified in the archive's model directory; solver licensing does not automatically resolve the models' rights.
- **Fit and gap:** Q22b, `CJ-WITNESS`, R-13-023a/b/c. A significant exemplar because concrete Merkle representations discharge assumptions used by the symbolic protocol analysis. Its simplified certificate model assumes the website successfully accesses and verifies the log; it does not supply this project's quorum-intersection, persistent recovery or witness-key-transition theorem. **Disposition: strong method and model exemplar, with licensing and witness-policy extension outstanding.**

## Logres: machine-checked Byzantine log replication

- **Authorship and standing:** Joel Wanner, Laurent Chuat and Adrian Perrig, [A Formally Verified Protocol for Log Replication with Byzantine Fault Tolerance](https://arxiv.org/abs/2009.10664), SRDS 2020.
- **Artifact:** the paper's [Isabelle source archive](https://www.dropbox.com/s/w679b3xem11gjx4/proofs.tar.gz?dl=1) contains `proofs/theories/ProofConsensus.thy`, whose `consensus` lemma states `P_validity` and `P_agreement`, alongside `ProofCoordination.thy`, `Protocol.thy` and `SigHOModel.thy`. README specifies Isabelle2019 and `make` for checked typesetting. `Protocol.thy` explicitly axiomatizes finiteness of the abstract node type.
- **License:** no license file is present in the inspected archive listing or source headers. The paper's availability is not source reuse permission. Request or locate an explicit grant before incorporating proof text.
- **Fit and gap:** Q22b and R-13-023c benefit from finite-set quorum reasoning, agreement and authenticated-history structure. Logres's round-based BFT replication assumptions differ from asynchronous checkpoint cosigning; fault bounds, synchrony and signature assumptions cannot be silently transferred. It does not establish changing witness policies or crash-persistent recovery. **Disposition: strong independently checkable proof exemplar in another prover, with licensing and model port required.**
