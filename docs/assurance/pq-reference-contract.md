# Post-quantum functional reference contract

This contract opens the shared-helper and scheme work in M3.4b. The normative algorithm editions are [FIPS 203, published 2024-08-13](https://doi.org/10.6028/NIST.FIPS.203) and [FIPS 204, published 2024-08-13](https://doi.org/10.6028/NIST.FIPS.204). Their publication pages and errata must be checked when qualifying a vector campaign. The selected parameter sets are ML-KEM-1024 and ML-DSA-87. This document does not change R-05-058, R-05-059, R-05-004a or the frozen suite.

The shared interface is a degree, modulus, root, transform layer count and inverse scale, together with canonical modular coefficients, polynomial addition, multiplication in the negacyclic ring, complete and incomplete transforms, little-endian bit packing, compression and centered reduction. ML-KEM uses seven transform layers and quadratic residue factors; ML-DSA uses eight layers and linear factors. A polynomial identity must state its degree and coefficient bounds. Equal results on selected polynomials are examples, not a general inverse theorem. General transform inversion requires the shape and inverse-root premises to be proved for each selected ring. General encoding roundtrips require width, coefficient bounds and alignment premises. Fixed-width fields reject malformed input instead of silently truncating a zip or padding a missing field.

The hash interface binds SHA3-256, SHA3-512, SHAKE128 and SHAKE256 to the local Keccak reference. Matrix sampling uses rejection sampling, not reduction modulo the ring modulus. Noise sampling consumes the prescribed bit groups. A finite sampling budget may report exhaustion; it must not fabricate a coefficient, reuse a byte or emit a partial polynomial. A fuelled signing loop reports exhaustion separately from success and makes no claim that every input terminates within that budget.

ML-KEM key generation, encapsulation and decapsulation preserve FIPS 203's byte encodings, matrix index order, seed domain separation, public-key modulus check and decapsulation-key hash check. Decapsulation compares the complete re-encryption with the received ciphertext and selects the rejection key on mismatch. ML-DSA key generation, signing and verification preserve FIPS 204's seed expansion, matrix and mask sampling, decomposition, challenge, hint encoding and strict response bound. Its Fiat-Shamir-with-aborts loop is distinct from ML-KEM's Fujisaki-Okamoto re-encryption check. The public signing wrapper binds the context and requires supplied hedging randomness under R-05-004a; an internal deterministic test input does not authorize deterministic production signing.

Acceptance requires compiled, assumption-audited definitions and theorems per file; positive cases with fully instantiated premises; an actual transform inverse theorem over arbitrary bounded coefficients; a codec inverse theorem at its stated domain; independent standard-vector campaigns for each executable scheme; and refusals for failed re-encryption, an over-bound signature response, noncanonical encodings and malformed lengths. Each vector record identifies an official source revision and bytes, operations covered, comparison method and any hash or extraction boundary. Locally generated examples are labeled as such and never described as standard vectors. Mutation results distinguish compilation failures, detected changes and unexplained survivors.

Acceptance is conjunctive. A structural scheme with abstract oracles, finite examples or an incomplete standard adapter does not close M3.4b. Any remaining arithmetic, sampler, signature or campaign work stays explicitly open. Computational reductions, target code refinement, binary constant time, masked hardware, entropy quality and production side-channel security are separate obligations.
