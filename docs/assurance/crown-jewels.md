# The Crown-Jewel Inventory

*The derived inventory required by **R-17-016a**. The [requirements register](../requirements-register.md) defines membership and remains the audited artifact under R-05-152. This view adds no obligations; any disagreement must be corrected here.*

## Why this document exists

Requirements R-05-046, R-05-050, R-05-076, R-08-028, R-12-043c, R-14-013b, R-15-221, R-17-012 and R-17-016 require this inventory or quantify over its members. R-05-151 requires each obligation to trace to the crown-jewel specification it constrains. The inventory makes those sets explicit.

A requirement **confers** crown-jewel status when its normative line identifies a specification whose fidelity to intent cannot be established by proofs against it. This document collects those conferrals. The register's **`CJ-` table** supplies coarser trace labels; it does not enumerate individual specifications.

Acceptance criteria can refer to an existing conferral but cannot create one. For example, R-11-015 relies on R-17-041's conferral, and R-13-009 relies on R-05-046's. `tools/check.py` reports a missing member, an unsupported row, an unknown requirement citation, or an undispositioned status assertion found only in an acceptance criterion.

## Why it matters for implementation

A crown jewel must be authored and reviewed. A proof can establish a property of a wrong specification without exposing the mistake (R-17-016). This inventory therefore identifies:

- **Review scope:** specifications needed by the independent release review under R-05-150, including the composition statement R-18-032 names.
- **Specification work:** artifacts needed before their corresponding proofs. The **Status** column records which exist and which remain incomplete or absent.

## The inventory

Status is a claim about *this repository*, not about the literature. ## The theorem targets

The remaining `CJ-` targets name **theorems, not specifications**, things proven rather than authored. They are not crown jewels in R-17-016's sense (a specification whose *correctness is unverifiable*, so that a proof matching it may still miss intent); a theorem's correctness is exactly what its proof establishes. They are listed here so that every target is accounted for, and because each one's premise includes a specification above or a judgment fixed outside this corpus, which is the seam structure R-18-031(a)'s machine-checked statement has to align with.

| `CJ-` target | Theorem | Proven against |
| --- | --- | --- |
| `CJ-COMPCERT` | CHERI-CompCert correctness | CompCert C semantics ⋈ the frozen ISA profile (row 4) |
| `CJ-SECOMP` | Robust preservation of compartment isolation by the verified compiler | the policy model (row 2) |
| `CJ-KERNEL` | Kernel functional refinement: the authored static separation kernel proved in Coq, seL4's endpoint model and non-interference statement taken as its design and the rest of seL4's object model deleted (R-07-001) | the kernel's abstract specification ⋈ the slot plan (row 17) |
| `CJ-RTL-SAIL` | RTL ⊑ Sail, functional and hyperproperty halves: a theorem rung of the refinement tower, *"the last an axiom and the rest theorems"* (R-05-158) | the ISA profile and its Sail semantics (rows 4, 6) |
| `CJ-CERISE` | The Cerise universal contract | the ISA profile and its Sail semantics (rows 4, 6) |
| `CJ-TAL-SOUND` | CHERI-TAL soundness: well-typed ⇒ safe over the Sail model | the ISA profile and its Sail semantics (rows 4, 6) |
| `CJ-ADMIT-IMPL` | Admission-checker implementation refinement: the shipped TAL evaluator accepts exactly where the pinned rule table does, the shipped CIC kernel exactly where MetaCoq's Gallina checker does, each within the resource contract R-06-015a declares | the judgment each checker is refined against: the pinned CHERI-TAL rule table and MetaCoq's Gallina checker, neither an inventory row (below) |
| `CJ-CT-SOUND` | Constant-time type soundness over the leakage model | the `Zkt`/`Zvkt` statement (row 5) |
| `CJ-REDUCTION` | The IND-CCA / EUF-CMA reductions | each primitive's functional specification (row 14) |
| `CJ-WASM-SOUND` | Platform-interpreter soundness and robust guest confinement: the executable interpreter refines the pinned semantics, and an adversarial module influences its host and peers only through its declared imports and exports | the pinned Wasm guest semantics (row 25) |

The split is one reason the inventory and the trace legend cannot be the same artifact (the other, granularity, is next). **A theorem with no specification to be proven against is not a deliverable**, so every row in this table depends on a row in the one above, or on a judgment fixed outside this corpus that the paragraph below accounts for.

Three premises above also name specifications the inventory does not carry: CompCert's C semantics, the kernel's abstract specification, and the judgment each admission checker is refined against. None is conferred, and their absence is the membership rule holding rather than an oversight. The first two are proof-interior interfaces of the R-05-019b shape, one Coq term two proof developments quantify over from opposite sides, and neither appears in the statement of T or of any property a requirement names, so a wrong one fails to link at R-18-031(b) instead of yielding a correct proof of a wrong property, which is the failure R-17-016 defines the status by; R-07-049 says it of the kernel directly, booking the residual as the capability-widened memory model and the refinement over it *"rather than the CHERI-C semantics itself"*. The third splits along its two halves and neither half reaches the status: MetaCoq's Gallina checker is that same proof-interior shape, and the pinned CHERI-TAL rule table is the one premise here whose correctness a theorem already covers, `CJ-TAL-SOUND` being the statement that those rules are sound, so a wrong rule fails the metatheorem rather than yielding a correct proof of a wrong property. The contrast with row 6 is what conferral is for: the Sail model sits between two proofs in exactly the same shape, but it also models the machine, and R-15-005 confers on precisely the fidelity no proof on either side of it checks.

## What the `CJ-` table is, and is not

Every target in the register's `CJ-` table is used by a `Trace:` line. A target can cover several specifications: `CJ-FORMAT` covers Narcissus descriptors and `CJ-CRYPTO-SPEC` covers primitives' functional specifications. R-05-046 and R-05-076 also require the individual members, which this inventory must enumerate as those inventories are authored.

## Standing obligations

- **Membership changes by amendment** (R-17-016). A conferral missing from this table, or a row without a conferral, is a review-gate finding reported by `tools/check.py`.
- **Every crown jewel is subject to independent review** under R-05-150 (R-05-046, R-08-028, R-15-221).
- **Every crown jewel has a `CJ-` trace target** used by the sections that constrain it (R-17-016). The Constrained-by column is that check made visible.
- **Status is maintained, not asserted once.** The inventory is revved with the register (R-18-034), and a status that moves from `not authored` without an artifact link is a finding.

## Reading the status column

The inventory rows identify each artifact, its status and its remaining scope; an authored reference model does not establish its implementation or the adequacy of its external premises.

The status column tracks R-01-003's specification work and the premises each theorem needs. New obligations may add rows; new artifacts may change their status. Read those changes alongside Git history and the [implementation plan](../../PLAN.md). A completed implementation milestone does not by itself complete a specification row.
