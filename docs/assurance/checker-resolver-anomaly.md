# The kernel checker's resolver-roots anomaly

This is Q35h's record in [the implementation plan](../implementation/implementation-checklist.md#q-assessment-actions). It takes F-486, the anomaly `rocqchk` raises on VST 2.17's Floyd closure, which [Q35e's record](c-refinement-foundation-qualification.md#vsts-non-iris-line) met and the proof gate reads as a missing summary, and reduces it to a standalone reproduction that copies no VST source; it reads the released checkers the guest holds against that reproduction, reads upstream's sources and issue tracker for a report or a fix, and reads whether the gate could obtain VST's summary around the anomaly without weakening its reading. No register entry moves here. F-486's disposition, F-463's review-gate act for VST's summary and Q35i's reading of admitted roots consume it.

**Result.** The anomaly is the checker's, not VST's, and it needs none of VST's particulars: a functor whose body opaquely ascribes a module that holds a submodule trips it the moment the functor is applied, and the same file with a transparent ascription checks. Every released checker in the guest from 9.1.1 on aborts on the trigger, eight non-blank lines, so no released checker from 9.1 produces a summary for any Verifiable C client of VST 2.17, whose own bounds admit only Rocq 9.0 to 9.3. Upstream's tracker carries no report of the message; the locked 9.3.0 release carries four of the 2026 module-system fixes as backports and still aborts, and the four δ-resolver fixes that stay on master under the `9.4+rc1` milestone are unmeasured against the shape. A report is drafted, not filed, and conditional on a master measurement. No checker flag reads the closure around the anomaly: the checker's `-admit` and `-norec` leave the admitted module unchecked, and the smallest admission, the one module with every other library named as a root, writes a summary of 282 names where Q35e's admission wrote 380, 60 of them the sealed fields of VST's soundness module itself, which the gate refuses. The source-side route, twelve of VST's seals made transparent ascriptions, is read to its scope and left unmeasured, since it needs the rebuild the cell forbids and a carried patch M1.1a would have to admit.

## Reduction

Thirty-three attempts, each compiled and checked at 9.2.0 and 9.3.0 with the same verdict at both, walked from VST's shape to the trigger. The shape: `SeparationLogicAsLogic.v`'s functor `DeepEmbedded` seals `CConseq` against `CLIGHT_SEPARATION_HOARE_LOGIC_COMPLETE_CONSEQUENCE with Module CSHL_Def := DeepEmbeddedDef`, with `Module CSHL_Def := DeepEmbeddedDef` inside the seal, and `SeparationLogicAsLogicSoundness.v`'s functor `DeepEmbeddedSoundness` applies `DeepEmbedded` to its own parameters and aliases a field of the result; `MainTheorem`, itself sealed, applies both. The first attempt in that shape aborted with a different message, `Type error: IllFormedConstant`, and the attempt that first produced the recorded message differed by typing the sealed module's one constant through the sibling module rather than through the module's own alias field; the second symptom is read below. From that attempt, each construct was removed or changed on its own:

| Construct removed or changed | The anomaly |
| --- | --- |
| The outer functor's alias of the application's field | stays |
| The inner alias, replaced by a structure defining `t := Def.t` | stays |
| The `with Module CSHL_Def := …` clause of the seal | stays |
| The outer functor's application | stays |
| The second file, both functors in one | stays |
| The sealed module's constant | stays |
| The sibling module, the alias naming the parameter instead | stays |
| The alias naming a module outside the functor | stays |
| The outer functor, the inner one applied once at top level | stays |
| The module field hidden by sealing against an empty signature | stays |
| The seal, made a transparent ascription `<:` | goes |
| The sealed module's submodule, a constant kept | goes |
| The ascription, the inner module left unascribed | goes |
| The seal moved to the functor's own result, no inner module | goes |
| The sealed module moved out of the functor, a functor aliasing it | goes |

What remains is [`Minimal.v`](../../tools/checker-reproductions/resolver-roots/Minimal.v), eight non-blank lines: one empty module type `S`, a functor `F (X : S)` whose body holds `Module M : S.` with `Module N. End N.` inside, one empty module `Z`, and one application `Module R := F Z.` The checker aborts with `Incompatible resolver roots: Repro.Minimal.R.M.N is not a subpath of Repro.Minimal.F.M.N`; [`MinimalTransparent.v`](../../tools/checker-reproductions/resolver-roots/MinimalTransparent.v), the same file with `<:`, checks with an empty axiom list. [`VstShape.v`](../../tools/checker-reproductions/resolver-roots/VstShape.v) keeps VST's names, its `with Module` clause and its alias inside the seal, and aborts naming `Repro.VstShape.DeepEmbeddedSoundness.DeepEmbedded.CConseq.CSHL_Def` and `Repro.VstShape.DeepEmbedded.CConseq.CSHL_Def`, the two paths F-486's message names under VST's prefixes; [`VstShapeTransparent.v`](../../tools/checker-reproductions/resolver-roots/VstShapeTransparent.v) and [`SealedNoSubmodule.v`](../../tools/checker-reproductions/resolver-roots/SealedNoSubmodule.v) are its two checking controls. The cell's Check clause names a variant without the triggering alias: in `VstShape.v` the alias `Module CSHL_Def := Def` is the sealed module's one submodule, so `SealedNoSubmodule.v`, which removes it, is that variant, and it checks under every one of the seven binaries. The reduction also shows that the aliasing itself is not what matters: the variant that puts a structure defining `t := Def.t` in the alias's place still aborts (the table's second row), so the trigger is a submodule under the seal, aliased or not, with the seal inside a functor body and the functor applied.

**Where it is raised.** `Mod_subst.add_delta_resolver` in `kernel/mod_subst.ml` refuses to merge two δ-resolvers unless the second's root is a subpath of the first's; the message prints the two roots. The two roots here are the sealed submodule's path under the application and under the functor's own path, so one resolver was not substituted from the functor's path to the application's before the merge. The checker reaches the merge from `checker/mod_checking.ml`'s `check_mexpr`, which re-elaborates a module whose implementation is an algebraic expression by `Modops.strengthen_and_subst_module_body` on the functor's path and `Modops.subst_signature` on its body; `kernel/modops.ml`'s `strengthen_and_subst_struct` is the one caller in that path that merges a submodule's own resolver into the enclosing one. Which substitution is missed is not decided here; the reproduction decides it for whoever repairs it.

## Workaround reading

The question was whether the gate could read a Floyd client's summary without the anomaly and without weakening its reading. The checker offers two ways past a module it cannot check, and `checker/checkLibrary.ml`'s `recheck_library` at `V9.3.0` states what each costs: the set left unchecked is the closure of the `-norec` roots less the closure of the checked roots, plus the closure of the `-admit` libraries, less every library named on the command line. So `-admit M` leaves `M` and its whole dependency closure unchecked, which is the reading Q35e took and the reason its admitted summaries named 363 sealed fields where the recursive ones named 204; and a library named on the command line is checked even inside an admitted closure, which is the one lever.

On the reproduction, in two files with a client requiring the second, the lever behaves as stated at 9.2.0 and 9.3.0: the recursive check aborts; `-admit Repro.Sound Repro.Client` checks the client alone and names the client's axiom beside `Repro.Sound.Main.S.DeepEmbedded.CConseq.conseq`, a sealed field of the unchecked module; `-admit Repro.Sound Repro.Client Repro.Base` checks `Base` as well and names the same two; `-norec Repro.Client` reads as the admission does. The admitted module's sealed fields are named as axioms whatever else is checked, because the checker has no evidence for them.

On VST itself the lever's smallest form admits `VST.floyd.SeparationLogicAsLogicSoundness` alone and names every other library the client's closure interns as a root. Q35e's client in vst2 interns 654 libraries; naming the 653 others, 203 of `VST`, 28 of `compcert`, 318 of `Stdlib`, 42 of `Corelib`, 24 of `Flocq`, 36 of `Ltac2` and the client's two, the 9.2.0 checker `2f48c345…` exits 0 after 5 min 11.41 s with a 2,084,304 KiB peak and writes a summary naming 282 constants, where this lane's re-run of Q35e's admission, the module with its whole closure, named 380 in 44.14 s: the same 17 declared axioms and parameters, the 204 fields of `VST.msl.shares.Share` and `VST.veric.compcert_rmaps.R` that F-487 names from the fully checked `SequentialClight` closure, `VST.floyd.canon.Conseq.semax_pre_post`, and 60 fields of the admitted module's own sealed submodules, `MainTheorem.CSHL_MinimumLogic` (38), `CSHL_PracticalLogic` (17), `CSHL_Def` (3) and `CSHL_Sound` (2). The 98 names that leave are exactly the fields of the libraries beneath the admitted module that Q35e's reading loaded unchecked and this one checks. The reading that matters for the gate is the 60: the admitted module is the one defining `MainTheorem`, Verifiable C's soundness statement, so the smallest admission leaves exactly VST's soundness module unchecked with its sealed fields named as axioms, and the gate refuses a summary naming any axiom outside R-05-164's declared set, which is empty. No flag skips the re-elaboration of an algebraic module expression, so no invocation reads this closure fully checked at any released checker from 9.1. The lever is the input Q35i's reading of admitted roots needs, and it changes nothing in the gate's code here.

**The source-side route.** The reduction also names two one-construct changes to the library itself under which the checker accepts the file: a transparent ascription `<:` in place of the seal, or no submodule under the seal. Read in VST 2.17's two Floyd sources in the vst2 switch, by line number and copying nothing, the first change's scope is twelve opaque seals holding a submodule inside the two functor bodies the message names. In `SeparationLogicAsLogic.v`, the functor `DeepEmbedded` (lines 364 to 3266) seals `CConseq` (382), `Extr` (992), `CallB` (1284), `Sset` (1298) and `Sassign` (1330), each against a signature with a `with Module CSHL_Def :=` clause and each holding `Module CSHL_Def := …` as a field; its `DeepEmbeddedMinimumSeparationLogic` (1232) and `DeepEmbeddedPracticalLogic` (2652) already ascribe with `<:`. ## The second symptom

[`AliasTypedField.v`](../../tools/checker-reproductions/resolver-roots/AliasTypedField.v) is `VstShape.v` with one constant in the sealed module, `conseq (x : CSHL_Def.t)`, typed through the module's own alias field. `rocq c` accepts it; `rocqchk` aborts with exit 129 at every release read, with the resolver-roots message at 9.1.1 and `Fatal Error: Type error: IllFormedConstant` at 9.2.0 and 9.3.0, which those checkers raise first; the same constant typed through `Def.t` restores the resolver-roots message everywhere. The checker's `IllFormedConstant` is its refusal of a constant whose canonical name disagrees with the one its resolver computes, the error #21816 reports from the compiler side; the two symptoms are read as one defect met from two directions, the second needing a constant for the checker to type before it merges the resolvers. The file alone checks when the application is removed, as the reduction's control shows for the first symptom.

## Disposition

- **F-486** stays open as an upstream defect, its statement widened from VST's module to the shape: the anomaly needs a functor sealing a module that holds a submodule, applied once, and every released checker from 9.1 raises it, so no Verifiable C client of VST 2.17 can be checked by any released checker VST admits except possibly 9.0.x, which is unmeasured. - **F-463**'s input for VST's summary is that no released checker from 9.1 produces a Floyd client's summary without admitting VST's soundness module, and 9.0.x, which lacks the root check, is unmeasured; the bounded admission's 282 names, the 17 declared, F-487's 204, `semax_pre_post` and the soundness module's 60 sealed fields, are the smallest summary the gate could be shown, and the receipt lists them.
