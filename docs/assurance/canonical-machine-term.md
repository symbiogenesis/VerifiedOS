## 1. How the term is emitted

`python tools/run.py model rocq` emits the term through the model's own CMake target `generated_rocq_rv64d` in [model/model/CMakeLists.txt](../../model/model/CMakeLists.txt), which runs Sail once from `model/model` and writes `rv64d.v` and `rv64d_types.v` under the `rocq/` directory of the lane's build tree, `/root/build/lane-<lane>/verifiedos-model`. [vos/rocqterm.py](../../tools/vos/rocqterm.py) and [the tool guide](../../tools/README.md) state the command's contract:

1. It deletes both outputs and the receipt before anything else. The target's `DEPENDS` name the Sail sources, the project file and the configuration but not the Sail binary, library or plugin, so outputs an earlier run left can satisfy the target without an emission.
2. It seeds and configures the lane's tree with the configure line `run.py model build` and `run.py model emit` share (`_configure` in [the model command](../../tools/vos/cli/model.py)), reads the target's Sail command back out of the tree with `ninja -t commands`, and refuses a missing frozen profile or a command whose `--config` is not it.
3. It runs `cmake --build <tree> -j 1 --target generated_rocq_rv64d`, refuses a run whose configuration, listed sources or toolchain moved while Sail read them, and writes the generation-identity receipt beside the term. A refusal after the build deletes what the build wrote, so no output stands without its receipt.

The Sail command the target runs, as the receipt records it with the lane's tree written `<tree>` and the checkout `<checkout>`:

```console
sail --strict-var --strict-bitvector --strict-exponentials --require-version 0.20.3 \
  --memo-z3-path <tree>/model/sail_smt_cache --drocq-undef-axioms --rocq \
  --rocq-lib riscv_extras --rocq-output-dir <tree>/rocq -o rv64d \
  --config <checkout>/model/config/verifiedos.json --all-modules riscv.sail_project
```

**The target's term is the canonical term.** The target names [verifiedos.json](../../model/config/verifiedos.json), the frozen profile's primary composition (F-478). The same command run directly from `<checkout>/model/model` in the Sail switch's environment, with `/root/z3-5.1.0/bin` first on the path, a fresh memo cache and a fresh output directory, emits the same bytes: [section 3](#3-the-digest-moves-with-the-model) compares the two at both of Q35f's source states.

`--drocq-undef-axioms` makes Sail emit an `Axiom` for each function the model declares and does not define for the target. The help of Sail 0.20.2 and 0.20.3 lists the option as `--rocq-undef-axioms`; this spelling is accepted and took effect, each emission before Q35f's removals carrying 85 `Axiom` declarations. The emissions at 0.20.2 ran each command with `--require-version 0.20.2`, the floor of that time. `--rocq` selects the backend Sail registers under the target names `rocq` and `coq`: the model's `$iftarget rocq` blocks are the term's, and the backend looks extern keys up under `coq` whichever name selected it (F-479). `--rocq-lib riscv_extras` adds `Require Import riscv_extras.` to the output, so [the model's Rocq support file](../../model/handwritten_support/riscv_extras.v) is an input to the compile and not to the emission. `--config` fixes the model's configuration into the term; [the configuration section](#4-the-configuration-the-target-emits-at) records which file the target names.

## 5. Undeclared axioms and how each can leave

This section lists every undeclared axiom and parameter that a source reading, and the probe below, places in the term's closure, and how each that has left did. It is not the closure as the gate reads it: the gate reads the kernel checker's whole-environment summary after compilation, as [the tool guide](../../tools/README.md#current-evidence-and-generated-documentation) states, and that compile is owed. R-05-164's declared set is empty, so the gate refuses every name the term or its support library still declares.

Three classes, following the plan's cell:

- **Model:** removable by a change inside `model/`, either a Rocq binding to an existing Rocq definition or to one added to the model's Rocq support file, or a Sail definition, deletion or Rocq-target guard that the backend emits from. This reads the cell's *definition in the model's Rocq support library* as including the model sources the backend emits that library's callers from, and is stated so that the review can refuse the reading.
- **Support library:** removable only by a change in `rocq-sail-stdpp`, or in the Sail library the locked emitter reads, both upstream artifacts at the locked pair.
- **Irremovable:** no definition at the pinned toolchain fixes the meaning, so the axiom stays unless the review gate admits it under R-05-164 or commissions a semantics that defines it.

Q35f's model-side removals have landed, so no axiom of the class Model remains in the term. Q35g's change to the support library removes the five the library loads from a term that loads the changed library without `SailStdpp.Real`, and [the routes below](#routes-that-take-the-five-out) state what each step still owes. A reduction that meets the model's internal error has reached a body the term gives a path no shipped composition executes: a half-width floating-point operation or an emulator-memory primitive, below.

### The quotient and remainder contract

The prelude binds `quot_round_zero` and `rem_round_zero`, and their nonnegative-dividend forms, to `Z.quot` and `Z.rem`; the C and C++ bindings are `tdiv_int` and `tmod_int`. For a divisor `m` other than zero, which every binding's type requires, `q` and `r` meet the contract when `n = q * m + r`, `|r| < |m|`, `r` is zero or has the sign of `n`, `|q|` is the floor of `|n| / |m|`, and `q` is zero or has the sign of `n * m`. [`/root/build/lane-q35f-axioms-20261002/q35f/quotrem/QuotRem.v`](../implementation/retained-evidence/root/build/lane-q35f-axioms-20261002/q35f/quotrem/QuotRem.v), SHA-256 `653a546fe6e8db03ce02974eae5167f9e8847fa42eb14f37fc0c021976c2e7a6`, decides it by `vm_compute` with the proof switch's Rocq 9.3.0, and [`/root/build/lane-q35f-axioms-20261002/q35f/quotrem/quotrem.log`](../implementation/retained-evidence/root/build/lane-q35f-axioms-20261002/q35f/quotrem/quotrem.log), SHA-256 `e590250fe624b10154fdf7a2d1708231e7b11e594a5d3f13024d88ede459e942`, records the compile:

- All 2,024 pairs of 46 signed dividends and 44 nonzero signed divisors meet the contract: zero, ±1, ±2, ±3, ±5, ±7 and the boundaries at 8, 16, 32, 64 and 65 bits, among them ±(2^31 − 1), ±2^31, ±(2^63 − 1) and ±2^63.
- The most negative 64-bit dividend over −1 gives quotient 2^63 and remainder 0, the unbounded integer the model truncates to the register width; over 1 it gives −2^63 and 0, and the 32-bit dividend −2^31 over −1 gives 2^31 and 0.
- Each sign quadrant rounds toward zero: 7 and 2 give 3 and 1, −7 and 2 give −3 and −1, 7 and −2 give −3 and 1, and −7 and −2 give 3 and −1.
- The nonnegative forms equal Euclidean division over the nonnegative dividends and positive divisors, as Sail's `div` and `mod` in their result types state.
- A zero divisor, outside the contract, gives quotient 0 and the dividend as remainder.
- The negative control: `Z.div` and `Z.modulo` fail the contract, so the check decides the rounding direction.

### The support-library change

## 7. Tracking decision

**The term is not tracked in this repository at this revision.** It is regenerated from the pinned toolchain by `run.py model rocq`, whose receipt states the identity, and a consumer of the primary composition's hart-0 term cites the canonical identity in [section 2](#2-generation-identity), or its own regenerated receipt beside that identity's inputs. A consumer of another composition or hart has no identity here (F-477).

- **Reproducibility.** At Sail 0.20.2 the canonical term was emitted twice, from two checkouts, and the target's twice in one lane, each pair byte for byte; at 0.20.3 the target and the direct command emit the same bytes at both of Q35f's source states, and [section 3](#3-the-digest-moves-with-the-model) names every difference from 0.20.2. The lock pins the Sail switch's versions, the solver's prefix pins its version and the base revision pins the sources; the recorded binary digests are the guest's `aarch64` builds and hold for that platform only. Agreement on another host or architecture is not yet measured; the first consumer that regenerates there compares its output digests with this record's, and its own binary digests stand beside them.
- **Staleness.** Every model edit moves the term, a moved source line included. A tracked copy would need a generated-artifact row with a guest-lane check like the bundle's, which is not this record's to add; untracked, the receipt pins what a consumer read.
- **The gate.** The term cannot enter `proofs/` while it carries the axioms above and the support library is absent from the proof switch, and a copy tracked elsewhere gives no consumer a checked object.
- **Licence.** The output is generated from the model, a modified BSD-2-Clause derivative of sail-riscv and sail-cheri-riscv, and from the BSD-2-Clause Sail library, and each file carries only the line `(*Generated by Sail from rv64d.*)` with no notice. Tracking it outside `model/` would place a whole-file derivative of the model there, so the tracking act would state its terms in [the licensing map](../../COPYRIGHT.md) and carry the BSD-2-Clause notice that `model/` retains. This record reads the map no further than that.
- **Size and consumers.** The canonical term's two files total 4,313,950 bytes, below the tracked model bundle, so size alone decides nothing. Q35c reads the term's definitions and Q35d reduces over it; each can regenerate in its lane with `run.py model rocq` and cite the identity.

The target binds the frozen profile and the model-side removals have landed, so the decision is revisited when the term compiles at the locked prover with the guide's library; tracking then comes with a generated-artifact row and a licensing-map row, owned by whoever tracks it.
