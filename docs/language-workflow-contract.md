## Operational subset and observations

The pilot is sequential, total, bounded byte-buffer code with fixed destination capacity, runtime length, proof-erased bounds, explicit failure results and a callback-shaped scoped loan. There is one authoritative executable definition per candidate component. Intended behavior is independently reviewed; generated implementations, representation code and proof scripts have named provenance and are regenerated, never manually repaired in place.

The operational source retains every value used for runtime branching, including length and result discriminants. A representation relation names byte order, integer width and overflow behavior, capability provenance, bounds and permissions, initialization, layout, and the correspondence between abstract owners and concrete bytes. The concrete laws must connect to the admitted CHERI-aware semantics. Importing a word-and-byte memory model, or assigning an integer address a capability interpretation in a printer, does not meet that condition.

For both clients, freeze a capacity `C` from the selected declaration, a stable readable source extent, an exclusive destination of capacity `C`, and their disjointness witness. `C`, loop indices and lengths have checked representations; the proof treats mathematical overflow boundaries even where an enormous byte array cannot be executed. No example treats a well-typed source length as evidence that it fits the receiver. In target measurements, input generation derives sizes from the frozen owner instead of maintaining a second list of layout constants.

### P: composed positive client

P combines the selected mechanisms in one executable definition and one theorem. The following is its behavior contract, not implemented pseudocode or a new source syntax:

1. Enter a scoped callback with the destination owner, the stable source read authority and a runtime length `n`. Validate `n` against the source extent and `C` before using it for a source access, destination index or pointer calculation.
2. Fill the entire destination with zero using a total repeatable callback returning the zero byte. The callback captures only stable public values, holds no competing destination loan and has no allocation or external effect. Its invocation count follows the destination bound, while capture and write permissions are proved separately.
3. If the length is rejected, return the declared invalid result with the initialized destination owner restored. Otherwise copy the selected source prefix into the private destination once, then check the staged header using the existing descriptor-check interpretation. Every validation read after copying is from the private destination.
4. Return success carrying the runtime `n`, its bound witness and the initialized destination owner, or invalid carrying the same initialized owner and the appropriate failure evidence. The original scoped loan cannot escape in either result. No branch changes destination capacity. The success result does not claim session-table validation that `DescriptorCheck` leaves to the receiver at use.

For every result, the source and unrelated frame are unchanged, the destination is wholly initialized, and ownership is restored exactly once. If `n` is admitted, the destination prefix equals the sampled source prefix and the remaining destination bytes are zero, even when header validation returns invalid. If `n` is rejected before copying, the destination is all zero and there is no source read. The returned status agrees with `Descriptor.descriptor_check` on the staged prefix for admitted lengths. An owner implementing different failure writes must reconcile the client contract before the freeze; the trial cannot compare different programs under one name.

These requirements exercise R-05-124's fixed-destination initialization, R-12-012a's receiver validation and the selected descriptor encoding obligations. They do not establish the complete parser, session validation or cross-compartment initialization theorem. A fixed immutable source for this sequential pilot does not discharge the Byzantine-peer or atomic-snapshot obligations of an executing service.

### S: held-out staging client

S uses the frozen generic disjoint-copy interface on the service's private staging destination. Its baseline records the staging lifetime, capacity, initial state and failure behavior M7.1 selects against `svc_op_record`; the statement artifact leaves those implementation decisions open. Freeze the accepted payload extent `d` separately from physical staging capacity `C`: the service's declared staging slack is storage headroom, not permission to accept a longer payload. Establish `d <= C` and test the payload and storage boundaries separately. For the comparison, the accepted slice has an initialized destination and copies `n` admitted bytes, preserves the destination suffix, source and unrelated frame, and returns its owner on success and error. A rejected length or extent produces the declared refusal without reading source bytes or modifying destination bytes. The result and exact failure status are fixed by the authored baseline before adaptation.

The expected successful payload is the first source prefix acquired by this sequential operation; no second source image determines the result. Input scenarios include changing the modeled later image while keeping the acquired one fixed. This checks the abstract behavior that `copy_once` specifies. It supplies no atomic-snapshot theorem for an adversarial writer, no concurrent SPSC theorem, and no publication, notification, cancellation, DMA or revocation result. Such a stronger claim requires its separate owner and connection evidence.

P and S have different initialization behavior by design. Each candidate is compared only with its own baseline, at unchanged behavior. Their shared generic operations must preserve those differences without adding client-specific CHERI representation facts to the generic theorem.

## Selected composition and rejection cases

The selected pilot interactions below are prospective qualification cases. None is executable evidence merely because it is described. All selected rows must compose in P; a missing mechanism makes the selected trial unavailable, with implementation separately assigned and priced before entry. Isolated passing feature examples cannot replace P.

| Interaction in P | Positive obligation | Well-formed negative neighbor and intended failure |
| --- | --- | --- |
| Stable indices and erasure | Use runtime `n`, fixed `C` and an erased `n <= C` witness in the bounded copy; retain the success/error tag | Erase `n` while branching on it, or retain the bound witness after changing the bound: reject at phase or stale-bound obligation |
| Mutation and dependency | Fill and copy change contents while preserving destination shape; old content facts are consumed | Use a pre-fill content snapshot to justify the final payload: reject at memory representation or functional postcondition |
| Scoped loans and results | Both callback result branches return the full owner and end the loan | Return the loan in the error payload, or propagate error without the owner: reject at escape or restoration obligation |
| Reusable callable, effects and count | Invoke the zero-byte callback at the proved loop indices with permitted captures and no external effect | Invoke a consuming callable twice; conceal a captured destination write or allocation; alias its capture with the exclusive output: reject respectively at usage, effect or disjointness obligation |
| Typestate and branch joins | The fill establishes whole initialization before either exit; the result's variant has its own bound and status facts | Skip one fill iteration yet claim whole initialization, read an uninitialized byte, or claim a successful parsed result on error: reject at initialization or branch postcondition |
| Name and instance resolution | Rename locals, qualify the buffer operation and import an unrelated module while retaining the same resolved constants | Silently select another representation or effect instance: require preserved meaning or explicit ambiguity, never stale acceptance |
| Dependent computation and automation | Compute bounded cases and replay equation lemmas and the exact transitive assumption audit | Add global UIP, leave a generated obligation open, or produce an executable term stuck on the selected concrete input: fail the relevant assumption, completeness or computation check |

Q19b's qualified definition mechanism is the only candidate for the last row; the contract assumes no new kernel conversion rule. A proved equality principle for the selected decidable index is distinct from an added global axiom. A proof-search service may suggest terms, but the saved reconstruction must replay without that service.

Straight-line borrow inference, a loan returned beyond the callback, disjoint-field and nested reborrow inference, resizing, suspension, cancellation, handlers, concurrency, general grades and a new frontend are **unavailable in this pilot**. General isolation, observation-policy and binary-leakage composition are **outside its source claim**. Q21's separately priced eventual-core trial decides those mechanisms. SPSC, DMA and atomic snapshots are **inapplicable to the sequential slice**, not established absences of the full system.

### Expected behavior, witnesses and mutations

An independent reviewer freezes the expected input/output table and checks before candidate proofs are authored. The expected bytes and status come from the client contract and the declared format, not by evaluating the candidate to make its own oracle. Include concrete inhabited entry states that satisfy the actual theorem hypotheses, plus these input classes for both matching baselines and candidates:

- Empty input, a single byte, exactly full input, and one beyond the declared capacity; S additionally tests `d` and `d + 1` independently of `C` and `C + 1`, including nonzero declared staging slack. P additionally covers every operation variant and every truncated field position the descriptor declaration admits.
- The last valid and first invalid index, malformed tag, direction, content and optional-deadline discriminants, and a flag outside the declared set. Retain distinct bytes at distinguishable positions to expose swapped reads or stores.
- Receiver-relative offset/length boundaries and arithmetic wraparound, proved at the selected word width. If a case is too large to execute, retain the proof case and report target execution as unavailable rather than allocate a different smaller substitute.
- Destination residue distinct from source bytes; nonempty frames around both buffers; adjacent disjoint ranges; and an overlap variant that is rejected at disjointness. Verify source and frame bytes on every exit.

Freeze explicit wrong-store, off-by-one, omitted-fill, bad failure-result and second-image variants. Each variant must first be syntactically valid and reach the intended obligation. Record separately: malformed or stillborn construction, killed at the intended obligation, unrelated failure, timeout, unsupported, and survivor. An unrelated parse, type or compilation failure supplies no evidence for an ownership or specification rejection. A survivor of a required negative case rejects the trial's successful verdict.

Use [the oracle, seed and QuickChick instruments](../tools/README.md#the-three-generators-and-what-each-answers) where the admitted source and endpoint are supported. A generated test does not replace independent specification review, and test guards do not become theorem premises. Every claimed guarantee names its supporting theorem. Remove a required frame-preservation guarantee theorem from an otherwise accepted instance while retaining its operation laws: P's frame-requiring client must fail for that missing guarantee. A profile flag or source ownership theorem supplies no adversarial-context isolation claim.

### Change and weakening probes

The required semantic edit changes P's accepted prefix bound from `C` to `C - 1` for the same nonzero destination capacity. Entry requires a concrete well-formed descriptor accepted at `n = C` under the frozen declaration and all representation hypotheses; nonzero capacity alone does not establish that witness. If no such witness exists, revise and independently review the probe before the trial opens. Before repair, the old success claim at `n = C` and its cached feedback must become stale or fail. Review the new intended behavior, regenerate the implementation and renew affected source, representation and artifact evidence. The expected-behavior table changes only through that independent review; the exercise records all source, contract, glue and proof edits. The unchanged baseline arm receives the identical semantic change before comparing repair cost.

The weakening probe removes the exact successful copied-prefix equality from S's postcondition while retaining bounds, initialization, frame and status. A wrong-store implementation can then satisfy a weaker statement. The independent expected-byte check must still reject its output on a nonuniform source. If that check cannot detect the omission, record a specification gap and refuse success. Inhabiting the weakened contract, completing a proof or showing only memory safety cannot close the gap.

Run a separate semantics-preserving local rename and helper extraction, the unrelated-import probe, and an instance representation change that preserves its public laws. The generic theorem must replay unchanged after the changed instance laws are reproved. Record saved-term replay separately from tactic or search rediscovery, including search seed, limit and reconstructed proof. New source maps, resolved constants, representations, contracts or dependencies invalidate their affected evidence even when a rendered goal looks unchanged. Any new unresolved hole, admission or assumption outside the exact R-05-163 declaration fails acceptance under R-05-018a and R-05-018b.

## Accounting and decision thresholds

This contract owns the experiment parameters below. They are predeclared selection rules, not measured facts or predictions. Review freezes them before opening Q20b/Q20c. Any amendment restarts the affected comparison under a new protocol identity and reports the prior outcome; it cannot retroactively turn a failure into a pass.

| Parameter | Threshold | Ground and interpretation |
| --- | --- | --- |
| Correctness and evidence | Every selected positive meets its exact endpoint; every required negative fails at its intended obligation; zero new admitted assumptions, stale acceptances or undetected selected weakening | The claimed guarantee is conjunctive; averaging safety failures would remove its meaning |
| Interactive diagnostic latency | p95 at most 2 s for the frozen incremental sequence | The pilot tests feedback usable within a local edit loop. Slow batch proofs remain separately measured, so an expensive kernel replay does not masquerade as an interactive result |
| Replay limit | Each warm replay completes within 10 min and each cold replay within 30 min | Bounds the experiment's usable edit/rebuild loop. A timeout leaves that attempt undecided and supplies no proof rejection; repeated limit failure rejects workflow adoption |
| Held-out recurring effort | Candidate upper bound at most 0.90 times the matched baseline lower bound, including learning, adaptation, review and the specified maintenance probes | A predeclared margin makes a nominal difference inside recording uncertainty insufficient for expansion; this is no forecast of a saving |
| Full accounting boundary | Conservative `NetSaved` strictly positive at the selected evidence endpoint | Both selected clients must repay all attributable setup and shared work within this bounded pilot before expansion is credited |
| Native footprint and runtime support | No larger declared stack or peak storage, no new allocation or undeclared runtime support, and unchanged hard resource bounds versus the matching manual baseline | The comparison cannot buy speed by consuming a larger admitted resource envelope |
| Native code and cycles | Final code size and each measured case's target cycles at most 1.05 times its matching manual baseline; no applicable hard bound regresses | A bounded experimental tolerance for competitive output, with failures exposed per dimension rather than hidden in a combined score |
| Selected optimization | Optimized cycles no greater than the same candidate's unoptimized cycles on any selected case, and total optimized code bytes no greater | This bounded trial retains only an optimization that preserves both dimensions; a deliberate trade needs a separately reviewed comparison |

The accounting period opens with the first attributable qualification/interface event and closes after P, S and the declared change probes reach the selected endpoint. Only these concrete planned consumers count. Source-workflow accounting closes at Q20b; Q20c extends the same ledger to final artifacts. The latter cannot inherit a production saving from the former. Further consumers, future targets and repeated imagined edits supply no adoption credit.

Use the strategy's [break-even equation](verification-language-strategy.md#where-time-might-be-saved) without adding another overlapping savings formula. The ledger assigns its terms as follows:

| Term or shared cost | Unique owner and treatment |
| --- | --- |
| Library/interface establishment `L` | Q19c; include attributable Q19a/Q19b qualification and initial learning here or at its original owner with a cross-reference, never at both |
| Shared maintenance `M` | The owner changing the common interface/tooling; client repair stays in that client's event series |
| Concrete instance `P_j` | Checked foundation owners identified by Q2c and Q19c's concrete instance work, attributed once to the actual endpoint; the foundation map's scoping cost is distinct from implementation cost |
| Baseline client effort `B_i` | Q2b for P, M7.1 for S; include the matched source, proof, review and maintenance work and baseline-specific prerequisites |
| Candidate client effort `A_i` | Q20b's adaptation and maintenance events, including its learning, glue and review; S's one adaptation is the same record Q19c consumes |

Existing common foundations appear in the full ledger once with their allocation rule; identical costs on both sides may cancel only transparently. Missing historic cost records make a full-establishment comparison unknown; report observed recurring work independently.

## Contract acceptance and remaining gates

Q20a is acceptable as a reviewed contract when the named clients, frozen-baseline procedure, selected composed case and negative neighbors, expected-behavior and weakening tests, source/evidence identities, sampling, cost allocation and thresholds form a consistent executable protocol conditional on its explicit prerequisites. `python tools/check.py` checks document consistency; it does not run this protocol or establish its semantics.

The review must decide that the independent expected-byte check detects the specified weakening, that each negative variant can reach its intended obligation from a well-formed starting point, and that each entry state can satisfy the theorem it tests. It checks all return states together and reconciles the source/IR boundary with Q21 and the foundation owners. A reasoned rejection naming an unresolved interaction is a valid design outcome; merely listing attractive mechanisms is not acceptance.

Q20b's successful record is **source-verified workflow evidence**. An actual complete source-to-image relation adds **artifact-connected evidence**. Only Q20c's complete applicable admission, resource, security and target record supports **production-qualified** at the claimed endpoint. None supplies the hardware refinement or a silicon performance measurement. The implementation and proof prerequisites remain open at their existing owners, and this contract grants no independent completion credit to them.
