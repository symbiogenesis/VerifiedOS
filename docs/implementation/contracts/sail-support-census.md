# Native Sail support module census

Q35q owns this prerequisite to its [native declaration inventory](../../../tools/opam/sail-compatibility.md#native-support-inventory-prerequisite). The [retained diagnosis](../q35q-native-inventory.md) identifies module-type fields that are not global constants and a sealed concrete functor result. Implementation starts after this contract is committed. Its scope is the exact selected support population in [the immutable recipe](../../../tools/opam/sail-support-qualification.json), at the existing locked prover, dependencies, strict flags and source patches.

## Census and provenance

Retain the complete native `Print Module` reading for each selected module and recursively read every nested module, module type and functor that reading names. Retain `Print Module Type` readings for signatures. Every native field receives one classification: an owned instantiated kernel declaration, an abstract interface obligation, or a proven abbreviation/alias. Every `Search` row is accounted for by native resolution and the corresponding field; source spelling alone establishes neither ownership nor completeness. Unsupported, incomplete or ambiguous readings refuse the census.

Module-type fields and the formal and result fields of unapplied functors remain explicit interface obligations. They are not ordinary global constants and must not be passed to `Print Assumptions` as though they were. Their complete names, types, enclosing signatures and functor parameters remain in the census. This classification permits no additional global assumption.

For concrete modules, including sealed functor results, use native canonical resolution to connect every exported field to its actual instantiated implementation. Audit that resolved declaration's exact assumptions. A printed signature or functor application without the implementation connection supplies no assumption verdict. Aliases retain both the printed spelling and native target; two spellings of one declaration need explicit alias provenance rather than duplicate acceptance. Foreign, missing, duplicate or ambiguous declarations refuse. An empty or alias-only module needs its complete native body and abbreviation/alias readings; an empty `Search` result alone is insufficient.

## Acceptance and controls

The common guard's owned canonical population stays separate from alias evidence.
Every concrete declaration alias and direct-reference abbreviation also binds its
native-proven audit target to an exact `Print Assumptions` result under the same
unchanged support allowlist. An already audited target can be reused only with
explicit source-to-target bindings; an external or sealed target cannot escape
the audit because its spelling is an alias. Abstract or bound interface references
remain obligations and authorize no global assumption.

The adapter passes only when the complete selected population and every printed row are accounted for, every owned instantiated declaration has its exact assumption audit, and native input identities remain unchanged. Keep the common inventory guard unchanged. The support-specific adapter supplies only independently established canonical declarations to that guard and preserves all original rows and provenance in its evidence. No prefix insertion, discarded row or unexplained empty result may turn a refusal into success.

Positive controls cover a signature-only module, an unapplied functor, a sealed concrete functor result and a proven empty/alias-only module. Refusal controls cover an omitted nested field, a signature field treated as a global constant, a missing concrete implementation connection, a foreign declaration, ambiguous resolution, a duplicate, an unsupported native module form and an unproved empty module. Controls run at the locked prover where native classification is claimed; Python fixtures alone qualify no native census.

Q35q still requires its complete real hosted census, exact assumption audit and recursive kernel check. Q35n's independent cold snapshot export/import campaign and Q35b's canonical consumer acceptance retain their separate predicates. This contract accepts no support carriage, proof, changed source semantics or project-lock update.

### Census continuation

This owner act commissions the remaining census in three bounded steps, after
this text and the [census schema](../../../tools/rocq-census/census-schema.json)
are committed. The schema is a separate acceptance boundary from
`verifiedos-rocq-native-metadata/1`.

1. Complete the native producer and original implementation resolver: at most six
   compile/query candidate checks or ninety active minutes, whichever comes first.
   Cover the selected population's ordinary and sealed structures, aliases,
   applied functors, formal/result signatures, inductives and abbreviations.
   Export native types and declaration contexts, typing flags, universes and
   quality constraints, module expressions, and implementation substitutions.
2. Complete the support adapter and locked native positive/refusal controls: at
   most three native candidate checks or thirty active minutes. Pure Python
   fixture checks provide focused feedback but do not qualify native behavior.
3. Run at most two standalone hosted support campaigns. Retain each attempted
   run's identity and exact verdict. A failed attempt permits one correction
   within the preceding steps' remaining budgets; it supplies no passing evidence.

Native controls include the actual `TypeCasts.ZEqdep` and `State_monad.NMap`
applications, a sealed implementation with a deliberately hidden control axiom,
and an actual abstract-field lookup refusal. Record that control axiom only as
expected control output; it never enters the support allowlist. The producer lane
owns these original Gallina controls and native unsupported-form refusals. The
adapter lane validates the emitted positive controls and applies explicit evidence
corruptions for omitted fields/connections, foreign/ambiguous/duplicate declarations
and unproved emptiness. Label these as adapter refusals over native-emitted data,
separately from prover refusals and Python-only fixtures.

Record candidate intent before launch, elapsed active time, exact source/input
identities, native exits and the separate evidence verdict. Read-only API study,
authoring and hosted queue/runtime are outside the active native-check budget.
Stop at budget exhaustion or the first native form outside the explicitly
commissioned coverage; retain its reading/refusal and return the missing act to
the owner. Never weaken a guard, drop a declaration, admit an axiom, or silently
broaden support to continue. Focused local builds and checks are permitted;
complete gates and benchmarks remain on GitHub Actions. Native processes use an
absolute temporary working directory, and compiled objects stay in the assigned
native lane. Installed and supplied objects are read-only and checked before and
after native execution.

Concrete implementation provenance records both exported and implementation
identities and the ordered substitutions connecting them. A canonical name alone
is insufficient for a sealed field. For a nested child of an applied or aliased
parent, retain the original child before the parent's substitution and its actual
instantiated child, with the complete enclosing module-descent chain. An already
substituted child cannot stand in for its original source. Do not re-typecheck serialized private terms
in the ambient environment: audit the exported concrete name through the locked
prover's native `Print Assumptions` implementation resolution. Abstract fields
remain obligations and never enter that query. The opaque native delta resolver
is represented by its complete effects over every enumerated field/reference and
native inline key; this is explicitly finite domain coverage, not serialization
of its private representation. Unsupported effects refuse.

Retain transparent-body identities and their complete native reference domains,
not executable library body ASTs. The locked native `Digest.BLAKE256` hashes the
complete constructor encoding in memory; source and instantiated identities remain
separate, with the same native substitution and assumption oracle requirements.
This keeps LGPL Stdlib functor implementation text out of distributed evidence;
the producer calls installed APIs and incorporates no upstream implementation.

The hosted route may record a separate `native-census-qualified.json` only after
all selected modules, native controls, exact assumption audits and recursive
kernel checks pass with unchanged identities. Its validator must replay the
adapter, assumption and kernel joins against retained raw readings. This record
can satisfy Q35q before a later snapshot export/import decision; it cannot satisfy
Q35n's independent cold portability predicate. A missing record, failed command,
incomplete population, unqualified implementation link or identity drift refuses
Q35q. The final handoff still requires Host CI and dispatches every Guest CI lane
without waiting for Guest CI.

no change to compiler strictness, dependency objects, source semantics, assumption
contexts or any acceptance predicate.
