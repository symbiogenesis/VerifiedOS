# Web application profile and qualification contract

**Profile: `vos-web-pilot/1`. Status: frozen qualification contract; no implementation or target qualification is claimed.** This is Q29a's deliverable in the [implementation checklist](../implementation-checklist.md#web-application-qualification). It selects a bounded experiment under R-14-008e through R-14-008j, R-14-009 and R-14-014. The [register](../../requirements-register.md) governs platform obligations; the [IDL profile](../../languages/idl-profile.md) governs types, encoding, manifests and ring lifecycles. This document owns only the pilot selections, budgets, cases and thresholds. It changes neither owner.

The [userspace strategy](../userspace-porting.md#web-applications-one-engine-and-a-capability-scoped-host) supplies the architecture. This contract freezes inputs before Q29b authors a pilot and Q29c measures it. A later change to a selection, budget, expected outcome or threshold produces a new profile version and a fresh review before measurements; a failing run cannot edit its own pass condition. Profile identity is the version plus the digest of these exact UTF-8 document bytes. Generated declarations and reports record both. No upstream API, source or licence is incorporated here.

## 1. Clients and identity

The hosted client, **H**, is an HTTPS checklist: load a fixed document and its assets, edit bounded text, explicitly save, close, disconnect the network and relaunch the saved checklist. The packaged client, **P**, is a byte inspector: choose an object through the trusted powerbox, count its bytes and line-feed bytes, and display the result. P runs the same operation first in interpreted guest code and then through a separately admitted native backend. Both clients have a tab, standalone-window and embedded-view presentation using the same admitted engine closure. A framework-specific launcher is not part of either client's behavior.

The pilot sources are authored by Q29b. The corpus records their immutable source and asset digests before Q29c runs. H uses a controlled HTTPS origin and a deterministic response corpus, not a changing public site. P's baseline and native operation receive the same immutable chosen object. Exact unsigned byte count and count of byte `0x0a` are the comparison oracle; this is neither text decoding nor a file-format parser. Empty input and the input limit are successful cases. Larger objects are refused whole, without prefix results.

| Descriptor field | Frozen meaning and validation |
| --- | --- |
| App identity | Stable composition-assigned identity, independent of display name, URL, signer rotation and asset digest; an update preserves it only through the existing admitted update policy |
| Profile identity | Separate browser-profile identity for tabs and private installed-app profile identities for H and P; presentations may bind the same installed profile only by explicit composition declaration |
| Content kind and origin | Closed choice of hosted HTTPS origin or packaged origin derived from app identity in a distinct package-origin namespace; package and HTTPS origins never compare equal |
| Start resource and navigation policy | H starts at its fixed HTTPS resource; P starts at a closure member. Internal navigation is confined to the declared origin. Other destinations open unprivileged bindings, never retarget an existing bridge |
| Engine and interfaces | Exact admitted engine artifact closure, embedding declaration digest, bridge declaration digest where present, and the IDL version obtained from the IDL owner; no version ranges or fallback negotiation |
| Assets and authority | P's authenticated asset closure and optional backend identity; H's retained offline asset set; generated manifest imports/exports and authority ceiling. A Web App Manifest is producer input only |
| Resources and durability | The budget record of section 4, declared durable object namespace, storage schema identity and update compatibility decision; no runtime expansion of these fields |

The live binding is `(generation, app, profile, origin, member, epoch)`, authenticated by the host's compartment/session binding. JavaScript never supplies or overrides it. A session-table handle additionally binds a slot generation, resource type and permitted operations. Window titles and integer equality are not identity checks. Epoch or handle-generation exhaustion retires the binding until reboot; wraparound and reuse of a live identity are refused.

Reopening the same origin in a different app profile gives separate DOM, heap, inline caches, cookies, storage, workers and grants. Sharing the immutable engine closure grants none of those. An embedding application's own capabilities do not enter the displayed content's binding. A remote frame, child frame or popup receives no custom bridge, including a same-origin child; the pilot permits the bridge only on P's explicitly bound top-level document.

The selected worker is a qualification subset of service-worker behavior, not a claim of complete Service Worker compatibility. It is scheduled only while its owner has an ordinary admitted slot. Offline lookup when H relaunches creates a fresh worker inside H's new binding, using retained assets rather than a surviving runtime. Concurrent worker threads, shared workers, shared mutable guest memory and cross-profile worker discovery are unsupported.

Push, background sync, persistent notifications, audio/video capture, arbitrary devices, clipboard access, remote fonts, WebGL/WebGPU, DRM, Node APIs, dynamic native modules, shell execution, filesystem paths and generic `invoke` are outside the pilot. Guest feature detection sees absent entry points where the corresponding web specification allows absence; where an exposed standard operation can be unsupported, the implementation must use its pinned specification's error. Q29b records the exact API and outcome in its generated inventory before implementation, and cannot expose a silently successful stub. Native bridge operations outside its closed declaration have no binding and are rejected if forged on the wire.

Standard compatibility, platform bridge behavior and framework source adapters have separate result columns. Replacing Tauri command plumbing in source may pass a bridge case; it does not pass a standard web test or establish compatibility with Tauri plugins, Electron, CEF or WebView2 binaries.

## 3. Embedding, bridge and service mappings

Use the IDL owner's [constructor rules](../../languages/idl-profile.md#2-the-type-constructors), [world/resource mapping](../../languages/idl-profile.md#5-worlds-manifests-and-resources) and [generated artifacts](../../languages/idl-profile.md#6-the-generated-artifacts-and-the-subset-a-coq-interface-is-stated-over). Q29b authors one pilot declaration that refers to the existing service types, rather than copying their definitions, and generates the guest API shape, native client/server bindings, manifest and proof skeleton from it. The same declaration fixes per-operation bounds, flow labels, validated-at-use fields, initialization states, result grades and cancellation records. No new IDL constructor or wire format is introduced.

The embedding world exposes typed create/present, navigate, focus and close operations over a view resource. Its import edges reach the existing shell/display and lifecycle services. Creation binds an existing pool member; it cannot allocate a compartment or alter scheduling. Navigation takes a bounded UTF-8 destination under B-url and applies the descriptor's policy before resolving it; no destination string is native authority. The app bridge world imports the object service and exports **inspect-bytes**, taking `borrow<object>` and returning a relevance-graded result containing `u32` byte and line-feed counts or a closed operation-specific error. It accepts no origin, app identity, path, executable name, offset or arbitrary operation selector. The host obtains the full object extent from the delegated resource metadata and validates it against the input bound before a read.

| WASI-inspired vocabulary | Pilot mapping and authority | Bound and lifecycle | Decision |
| --- | --- | --- | --- |
| Descriptor read | Existing object/store service; read-only object selected by powerbox, then a session-table index for the native inspection borrow | Whole immutable extent within B-input; service checks type, direction, generation and authority before access; no retained capability after terminal completion | Selected as an internal backend operation, not a general guest filesystem |
| Monotonic clock | Existing time service through the composition's declared clock interface; browser event timing only | No clock setting, timer-driven tenant creation or deadline outside the admitted slot; clock domain/units are fixed by the referenced service declaration | Selected for the runtime's existing timing needs; no new custom guest clock bridge |
| Random bytes | Existing crypto service only when an admitted browser protocol needs them | Bounded request from that protocol's declaration; no raw TRNG register, direct root draw or caller-controlled entropy source | No custom random-data bridge in this pilot; H's HTTPS stack retains its own crypto obligations |
| Sockets, path lookup, process and environment access | n/a | n/a | No adapter; ordinary hosted networking stays behind the browser's confined network service |
| Async resources | Existing request/completion lifecycle | B-calls and operation deadlines; no `future`, `stream`, Canonical ABI or Component Model runtime | A guest Promise facade only |

An accepted inspection holds its borrowed resource until the terminal point defined by the IDL [cancellation and generation rules](../../languages/idl-profile.md#435-cancellation-generation-and-dma). This pilot declares inspection non-cancellable at the operation level: a cancellation request receives the owner's defined answer, not a made-up successful cancellation. Navigation still tears down the session. Resource reclamation waits for the operation's bounded cleanup, revocation barrier, quarantine and any service completion required by R-14-009. No bridge operation issues DMA.

Submission reserves request and completion capacity together. A full request queue returns the ring's typed exhaustion result with no enqueue; the Promise facade exposes that refusal. While the document lives, each accepted call settles its Promise exactly once from the matching terminal completion, after the native adapter explicitly handles the graded result. Guest code ignoring a Promise does not waive native relevance obligations. Timeout is not successful cancellation and does not release a borrow. The terminal deadline includes cleanup and is part of the admitted operation record.

At navigation, redirect, revocation or close, the host first disables new calls under the old epoch, then initiates ordinary session teardown. Old document execution stops; no Promise callback, result bytes or authority can be delivered to its successor. A completion racing teardown is either delivered to the still-live old document before retirement or consumed by the retiring adapter for cleanup. It is never retagged. A destroyed document needs no in-document Promise settlement; the IDL's out-of-band session teardown is the logical terminal outcome. A new binding cannot reuse the old table, queues or memory until the full Reusable predicate holds.

## 4. Budgets, eviction and persistence

These are authored **pilot ceilings**, not measured platform capacity or product limits. A composition unable to provide them is ineligible for this experiment; unused capacity supplies no authority. Q29b emits these parameters into its declaration, and Q29c reads the generated values instead of maintaining another table. Every worker, frame and outstanding request is charged to its binding. Remote frames consume separate pool members and have no bridge.

| Parameter | Pilot value | Full-bound outcome or rationale |
| --- | --- | --- |
| B-pool | 8 identical origin members | Evict only within the equivalence class below; never mint another member |
| B-first | 16 MiB first-class private memory per member | Allocation exhaustion follows the guest-language or origin-restart rule; no borrowing |
| B-second | 64 MiB second-class private memory per member | Same containment; placement and tags still need an accepted memory plan |
| B-engine-first | 32 MiB shared immutable engine image in first-class memory | Reject a larger pilot image; sharing is charged once by the composition |
| B-engine-second | 128 MiB shared immutable engine data in second-class memory | Reject a larger immutable closure; mutable state is never charged here |
| B-assets | 8 MiB retained assets per app profile | Refuse a cache/package population that exceeds the budget |
| B-durable | 1 MiB user data per app profile | Atomic save refusal preserves prior committed bytes |
| B-store | 256 MiB total pilot-owned stored closure, both update generations and retained data included | Reject an update that cannot stage within the reservation; shared non-pilot services are reported separately |
| B-input | 65,536 bytes per selected object | Refuse larger objects before access; this also bounds baseline guest work |
| B-text | 4,096 UTF-8 bytes per checklist text value | Refuse longer input; byte length and scalar validity checked before storage |
| B-list | 32 checklist entries | Refuse insertion at capacity without discarding an existing entry |
| B-url | 2,048 UTF-8 bytes per destination | Reject invalid encoding or a longer destination before resolution |
| B-asset-count | 256 members per retained asset set | Refuse a larger closure even when its bytes fit B-assets |
| B-dom | 1,024 DOM nodes per document | Refuse pilot content exceeding the selected surface; dynamic exhaustion contains the origin |
| B-workers | 1 worker per live origin member | Refuse creation beyond the bound, with no extra pool member or slot |
| B-events | 16 queued events per member | Refuse the new event rather than overwrite or acquire another queue |
| B-calls | 4 outstanding inspections per P binding | Request and completion storage reserved from the declared per-member memory |
| B-handles | 8 delegated object handles per binding | Refuse new delegation when full; stale/retired slots do not count as free |
| B-epoch | Unsigned 64-bit epoch and handle-generation fields | Retire on exhaustion rather than wrap |

Slot widths, operating points, memory placements, resource-specific Reusable bounds and the foreground/background rung are **required composition inputs**, not invented by this table. They must satisfy section 5 and the existing admission proofs together. A blank, symbolic or unqualified timing input permits functional development only and refuses a target timing verdict. Workers, event callbacks and Promise continuations run in the owner's existing slot. Installed content creates no independent wakeup, tenant or priority.

For this pilot, an eviction candidate has the same confidentiality label and app/profile as the requesting binding, is not focused, consent-bearing, audio-active, mid-transaction or non-checkpointable, and has explicitly committed its durable work. Select the least recently focused candidate, breaking ties by composition-assigned member index. Discard its volatile execution and retain its declared durable objects; do not serialize JS heaps or native handles. Rebinding waits for the full Reusable predicate, not a published free bit. The reuse ceiling is T-reuse below. A request with no eligible candidate, including an all-protected pool, remains unopened and shows a trusted capacity-unavailable result within T-capacity; no foreign-label or protected victim is selected. This is the R-14-014 all-protected outcome, not a new platform compartment-allocation path.

Record eviction events, reason, candidate class and reuse duration in the existing bounded capacity telemetry under R-16-027. Q29c reports events per minute over each run and repeated eviction of the same binding; it cannot hide thrashing by reporting only successful launches.

Saving H's data and installing its offline set are separate atomic store operations. Killing the worker during a cache update leaves either the previous complete set or the new complete set, never a mixed shell. A cache response does not acquire package-script provenance. P's package closure is immutable and its chosen-object grants are volatile. Across reboot only declared durable objects and retained asset identities survive; grants, sessions, requests, workers and guest heaps do not.

A successor generation binds the new engine, assets, backend, manifest and handler registration together. The pilot keeps the same durable-data schema, so no migration is presumed. An incompatible schema refuses this update unless a separately admitted migration is supplied; that migration is outside this pilot. Recovery exposes the old or new complete admitted generation and the last committed durable data, never mixed versions. Rollback follows the existing anti-rollback policy; the experiment cannot authorize a forbidden older generation.

## 5. Numeric workflow thresholds and measurement

These values are selection thresholds for this small deferred-browser pilot. They are not measurements, promises for arbitrary sites, or amendments to the first-release floor. A stricter platform obligation always wins. Q29c must preserve them for its comparison; failure returns an implementation gap or a separately reviewed profile revision.

| Threshold | Value | Endpoint and eligible evidence |
| --- | --- | --- |
| T-launch | 2,000 ms maximum | H/P cold launch from shell activation to first usable painted controls, including asset validation and member binding |
| T-input | 100 ms maximum | Input receipt to the paint reflecting it, for every selected workflow while foreground |
| T-frame | 33 ms maximum | Consecutive presented frames during the declared continuous-scroll phase; missed frames remain in the sample |
| T-bridge | 250 ms maximum | Accepted inspect submission through terminal result delivery and borrow release, at B-input and B-calls load; user chooser time excluded and separately reported |
| T-capacity | 100 ms maximum | A full pool, queue, cache, handle table or explicit data limit to its declared refusal visible at the live requesting surface |
| T-reuse | 1,000 ms maximum | Teardown initiation to resource-specific Reusable, including outstanding operation cleanup, revocation and quarantine |
| T-background | 2,000 ms maximum | One already queued bounded offline-cache event to completion in the ordinary background rung while H remains live; no progress promised without an admitted slot |
| T-recovery | 30,000 ms maximum | Reset release to an offline usable H/P after a locally staged admitted successor generation, preserving committed durable bytes |
| T-repeat | 100 runs per client, surface and backend mode | Every run includes cold launch, edit/inspect, continuous scroll, focus loss/return and close; no discarded warm-up failures |
| T-scroll | 10 seconds per run | Fixed scripted input cadence and viewport frozen with the corpus; report every presented-frame interval |

All latency limits are maxima over their measured population, not percentile allowances. Also report median and p95 without letting either override a failure. Measure input, paint, IPC and reuse timestamps in a declared common clock domain or provide the checked conversion and its worst-case error; add that error to the measured upper bound. Missing samples, clock regressions, uncompleted accepted requests and timeouts are failures, not censored observations.

Run each client in each presentation on the same admitted engine closure and composition. P has interpreted and native modes with identical input bytes and rendered output. Report guest parsing/execution, marshaling, queue wait, native work and painting separately; the end-to-end result remains the adoption quantity. The native variant is retained for performance only if it passes every functional and isolation case and improves median end-to-end inspection latency by at least 20 percent without worsening any maximum threshold or budget. Otherwise retain the interpreted client and record a rejected acceleration experiment; Q29b's bridge exercise can still be useful evidence. Packaging receives no performance credit by itself.

Peak private memory is measured separately by memory class, including allocator reservations, worker/event/request storage and withheld-for-reuse memory. Report immutable executable/data bytes, stored closure, staged update bytes and shared service costs separately. Passing requires every B ceiling, no undeclared pool use, identical admitted schedule before/after installation, and the ordinary foreground/background policy during all phases. Exceeding a budget is a pilot failure even where its containment response is correct.

Host executions decide behavioral comparisons and host-relative speed only. Target wall time needs the selected schedule and qualified timing evidence under R-17-041, or qualified hardware; a functional Sail retirement count and host elapsed time cannot decide these millisecond limits. Report locally staged reboot recovery separately from build, proof, fetch and user-consent time. No total production update-latency claim follows from T-recovery.

## 6. Qualification corpus and refusal oracle

Q29b freezes sources, viewport, input cadence, object bytes, response transcripts, actions and expected observations before Q29c measures. Boundary values come from the declaration: empty, one below, exactly at and one above every representable bound, plus truncated encodings, invalid UTF-8 and unknown variants. Reuse existing generated IDL/ring campaigns wherever they apply; an authored integration scenario is not a second byte-level oracle. The table defines integration scenarios rather than claiming executed tests.

| --- | --- | --- | --- |

| W-guest | Interpreted JS and optional Wasm count the same corpus bytes | Wasm overgrowth fails in-language; JS memory exhaustion follows origin restart | Restart returns no old guest heap, inline cache or host import |

For each supported standard feature, the Q29c report names the exact pinned WPT, test262 or Wasm test identifiers and versions selected before execution, their applicability decision and expected result. Absence of an upstream test adds a named local test, not an inferred pass. Web API/JS tests outside their declared subset are reported unsupported; the shared Wasm engine owes complete Core 3.0 under R-14-013b, with all missing core cases blocking its acceptance; failures inside it cannot be reclassified after the run. Run interpreter cache-enabled/disabled comparisons under R-14-008d. Upstream engine results, standards conformance and admitted safety proofs are separate evidence columns.

The report binds profile bytes, declaration, generator, source closure, compiler/prover identities, admitted artifacts, composition, schedule, input corpus and instrument identities. For each case it records actual output, pass/fail/blocked/unsupported, refusal reason, resource high water, timing population and evidence path. A missing target or proof input produces `blocked`, never a successful aggregate. A machine-readable report is the owner; any reading view and totals are generated. Q29c owns that report instrument, so no hand-maintained result table is created by this contract.

## 8. Contract review and release boundary

Q29a is decided by reading sections 1 through 7 against its checklist predicate: identity and immutable resolution are fixed; every selected feature has positive, refusal and lifecycle cases; constructor narrowing, world generation, resource borrowing and Promise completion use the existing IDL; budgets and workflow limits are numeric; missing joins have explicit owners and estimate locations.
