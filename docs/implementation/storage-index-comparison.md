# Storage index comparison

Q22f qualifies a bounded comparison for R-10-004 in the [requirements register](../requirements-register.md). The result is a design experiment; [M5.3](implementation-checklist.md) owns the executable storage path and its target measurements. The current Bε design remains the incumbent until the actual composition satisfies the selection predicate. A successful synthetic case admits no product configuration.

## Predicate fixed before measurement

The fixture models existing-key overwrites in a height-two tree: one root, sixteen leaves, forty-eight fixed 64-byte key/value records per leaf, and 4 KiB blocks. Both arms use this same useful capacity, fanout and physical block size. The buffered arm reserves forty-eight 64-byte messages inside the root, alongside a 128-byte header and sixteen 32-byte child-address/authenticator slots. The plain CoW B+ arm leaves that message area unused. These magnitudes deliberately make full-buffer, duplicate-key and all-child cases small enough to enumerate. They are experiment inputs, not values taken from the register or a qualified NAND part.

The required resource envelope is fixed as follows before either arm is run:

* Useful capacity: the entire declared key domain remains representable, with every acknowledged overwrite visible and an unchanged retained snapshot readable. No insertion, split, merge, deletion, variable-length extent or extra snapshot is admitted.
* Space: at most 72 device blocks. The reservation covers a retained snapshot, the current tree, a fresh full-tree CoW transaction, its full-block redo payload and commit block, two root-publication slots, and one spare block. Shared subtrees can reduce actual occupancy; the reservation takes no sharing credit. Allocation, reclamation, replication and FTL metadata lie outside this index-only fixture.
* Working memory: at most 36 blocks, reserved before execution for seventeen candidate node images, seventeen redo images, one root/query scratch block and one leaf scratch block. A buffered message consumes root bytes, not an additional allocated block. Host Python memory use is not this reservation or a target measurement.
* Endurance: evaluate the same workloads at budgets of four, five and six device-block programs per acknowledged 64-byte overwrite, including journal payload, commit publication, home writes, checkpoint publication and the final complete buffer drain. Five is the central illustrative budget; the adjacent budgets expose sensitivity instead of presenting that arbitrary choice as a product requirement. Report byte amplification as well as programs per overwrite. Physical NAND erase/endurance and FTL amplification remain unknown; only under an explicit one-block-program-per-modeled-write assumption can these programs stand for NAND programs.
* Latency: each transaction or final drain needs at most 36 block writes and the declared bounded number of read/scan steps; recovery needs at most twenty block reads and eighteen writes, including checkpoint publication. Each cold lookup needs at most two block reads, sixteen child checks, forty-eight leaf-key checks and, for the buffered arm, forty-eight message-key checks. No amortized figure substitutes for these bounds. Three ordered persistence barriers per transaction and two per successful recovery are charged separately. The actual device service, integrity computation and CPU step coefficients are unknown, so neither microseconds nor WCET is inferred.

Workloads contain 192 overwrites, in transaction widths one, four and sixteen: one duplicate hot key, a cycling hot leaf, striped leaves, and deterministic affine key sequences. A separate exhaustive small-key family exercises message visibility and drains. Boundary probes cover a full root buffer, one-over-full insertion, a final drain touching all children, every redo length, every crash prefix and corrupt/misdirected payload records. Complete drain is included even when its cost makes a short workload fail the endurance budget. No threshold is relaxed after a result is observed.

Each arm passes a bounded case only when it preserves the map/snapshot and stays within all resource bounds and that case's endurance budget. A case neither arm serves is rejected. A B+ advantage may motivate a later composition only when its admitted cases meet the actual composition's requirements and its proof obligations are demonstrably smaller. Passing these fixtures alone cannot replace the incumbent or validate it on the device.

## Shared journal, recovery and integrity contract

The fixture instantiates the open parameters in [JournalIndex.v](../../proofs/JournalIndex.v); it neither executes nor refines that statement artifact. It selects a prefix redo log, one transaction outstanding, no background checkpoint overlap, and authenticated full-block redo images. A transaction with `p` changed nodes writes `p` redo blocks, persists them, writes and persists one authenticated commit block, writes `p` fresh home blocks and one alternate authenticated root checkpoint, then persists the checkpoint before reusing the journal. Acknowledgement follows that final barrier. Both arms pay `2p + 2` writes and three barriers. Changing that acknowledgement/checkpoint policy changes this experiment's cost model for both arms.

The valid commit binds the payload length, record order, target addresses and content identities. A crash before a complete commit selects the previous committed map. A complete commit with intact payload replays to the new map, including a partially completed home copy or final drain. A complete commit with a torn, corrupted or misdirected payload refuses recovery; it cannot silently discard an acknowledged generation. Repeated recovery is idempotent, and the journal remains reserved until checkpoint persistence. An interrupted recovery can repeat the bounded recovery operation; arbitrary repeated power failure has no finite aggregate liveness bound.

Integrity is an ideal equality check over symbolic node images and target identities. It is the same in both arms and supplies no AEAD implementation, collision bound, replay protection or cross-domain confidentiality theorem. The recovered root includes its pending messages: recovery need not flush them before serving reads. The final quiescent drain is separately charged. Fresh blocks never overlap the retained snapshot, and reclaimed old current-tree blocks are available only after successful checkpoint publication.

The B+ arm updates each touched leaf and the root once per transaction. The Bε-shaped arm appends messages in order; whenever its root exceeds capacity, it flushes the most populated child's messages, ties by child index, applying that child's messages in order before removing them. One transaction writes each changed leaf and the final root once. A lookup selects the newest matching root message before its leaf value. This is a bounded one-buffer comparison, not the multilevel VeriBetrFS algorithm or a second filesystem implementation.

The temporary message sequence can exceed the packed root's capacity by one transaction. Its raw 64-byte records fit one scratch block; the child counters and incoming-transaction bookkeeping fit the other, while candidate leaf images occupy their already reserved slots. The final persisted root must fit its smaller declared buffer. Each flush scans pending messages once to count child populations and once to apply/remove the selected child; there are at most sixteen selected children per transaction. The reported scan count excludes integrity computation and bookkeeping, which still need target coefficients. A cold transaction reads the root and each changed leaf at most once. These are sequential fixture reservations, not a verified layout of Python objects or concurrent target workers.

## Proof scope and prior art

Both arms owe key ordering and lookup refinement, CoW ownership and retained-root preservation, authenticated child resolution, atomic publication, crash refinement, bounded resource and liveness proofs, then implementation and binary correspondence. The buffered arm additionally owes message order and duplicate precedence, pending-message lookup equivalence, flush preservation and termination, and an invariant joining buffered updates with recovery. The B+ arm removes those particular obligations in this fixture. This is a structural obligation comparison, not a measured proof-size or proof-effort claim; splits and general tree height remain outside both experiments.

[VeriBetrFS's own repository](https://github.com/vmware-labs/verified-betrfs) identifies a verified key/value store based on BetrFS and its layered Dafny development. [BetrFS's FAST paper](https://www.usenix.org/conference/fast15/technical-sessions/presentation/jannen) identifies its Bε write-optimized index. [bcachefs's principles of operation](https://bcachefs.org/bcachefs-principles-of-operation.pdf), performance overview and node-structure discussion, describe a B+ tree with large internally logged nodes and journalled updates. That node-internal logging is distinct from the inter-node buffered-message refinement being compared here. None of those sources supplies this project's Coq/Iris proof or the fixture's measured results. No upstream code is incorporated.

## Reproduction and disposition

Run `python tools/run.py storage-index --json` for every measured workload, budget disposition, bounded semantic/crash population, reservation and input-source digest; `python tools/run.py test --only storage_index` exercises its behavioral and rejection checks. The predicate precedes the executable experiment in commit `38cebaa`; the [Q22f completion record](completion-log.md) owns the measured execution evidence. Results are emitted from the implementation, with no separately maintained measurement table here.

**Retain the Bε incumbent provisionally; admit no target composition from this experiment.** Under the central synthetic endurance budget, buffered singleton-update cases pass and their B+ counterparts fail. Under the strictest budget those same cases reject both arms; the wider budget admits both, and the larger transaction widths admit both throughout the declared budget sweep. Buffering therefore has a demonstrated use under this conditional full-block redo cost, while application transaction batching changes the comparison. B+ removes the fixture's message-refinement obligations, but that advantage does not satisfy the central envelope's singleton endurance requirement. Neither arm receives a global performance or proof-cost claim.

The map checks use direct ordered overwrite replay independently of the index lookup routine. Recovery checks compare serialized node images to an independently constructed committed map and enumerate interrupted full drains with the retained redo. Integrity failures refuse the committed payload. These finite checks establish only the fixture's behavior: the journal is a symbolic authenticated-prefix policy, the block device has no timing or NAND controller, and the fixture does not execute `JournalIndex.v`. That statement artifact's alternative recovery discipline remains open to M5.3. Target service/crypto costs, NAND erase and write amplification, admitted workload, final geometry, multilevel flushing/splits and the implementation/refinement remain open inputs. The applicable M5.3 owner must fix them and re-evaluate the same capacity, endurance and worst-case predicates before either index can qualify.
