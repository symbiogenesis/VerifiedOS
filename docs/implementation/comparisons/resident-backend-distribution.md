## 2. Deliverable and proof scope

Under [R-18-004e](../../spec.md#r-18-004e) and [R-13-027](../../spec.md#r-13-027), the first-release composed configuration ships the certifying compilers, prover, composer, and package-construction passes as admitted Tier-2 compartments. Every generation the device runs must be producible offline from its authenticated store's source closure: R-18-004e requires building and launching a changed Wasm bundle in one generation (`R-14-013e`), then composing, signing, admitting, and booting two native generations (one modifying a native package, one rebuilding the base image to `R-13-026`'s reproducible bytes). Under [R-13-027a](../../spec.md#r-13-027a), toolchain compartments hold declared [R-08-046](../../spec.md#r-08-046) bounded pools, no execute, sealing, or wiring authority over outputs, and run either in an admission-proved composition mode (`R-11-018`) with step-budgeted activations or in the desktop elastic domain (`R-07-037e`) with yield bounds (`R-07-037h`), while on-device `CHERI-TAL` and `CIC` checkers remain fixed-tier (`R-07-037f`). Across all three routes, [R-06-014](../../spec.md#r-06-014) leaves the De Bruijn bootstrap root relocated rather than closed: the resident checkers cannot certify themselves and co-bootstrap with the compiler, so trust rests on reproducible builds, diverse double-compiling (`DDC`), and RoT boot-chain measurement.

- **Route A** delivers HoldFast-authored IRs, optimization passes, instruction selection, register/stack allocation, assembly, linkage, image formation (`Q25dd`–`Q25dj`), and verified self-hosting (`Q25dk`) over the [native verified compiler and self-hosting contract](https://github.com/symbiogenesis/HoldFast/blob/a53d7752081cf72ba325092e38508dc45af353ce/docs/extensions/unified-source-contract.md#native-verified-compiler-and-self-hosting). Proofs must bind directly to the generation's canonical Sail/machine semantics (`R-05-019b`), transport contextual security, relational leakage, and hard resource bounds, and satisfy `R-05-023a`/`R-05-026` final-byte admission without depending on CompCert or LLVM. Self-compilation under `Q25dk` requires connecting the proved compiler definition, reviewed seed, and successive compiler images; reproducibility alone proves no soundness.
- **Route B** delivers the purecap backend authored in the contained `verifiedos-cheri-compcert` tree (`M1.2a`–`M1.2g-ii` over `upstream/SECOMP` at `cbef9c33`'s stock `riscV/`, paired with `M1.4′`'s in-tree assembler and composer).
  Parent `M1.2` still carries two open findings recorded in [the project plan](../../../PLAN.md): `F-520` (`upstream/SECOMP` lacks a checked robust-preservation theorem because `RSC.v` fails to build on `ccs-main`, `recomposition`/`link_compatible` axioms imply `False`, and `BacktranslationProof2.v` is excluded / `step_fix_fix` is admitted in `ccs-backtranslation`; see [SECOMP proof reuse](../../assurance/proof-reuse/languages.md#secomp-robust-preservation-components-with-an-unfinished-join)),
  and `F-521` (contained builds currently use unlocked Coq 8.20.1, OCaml 5.4.0, and Menhir 20260209 pending `Q39`'s locked-switch build).
- **Route C** delivers only the enumerated dual-licensed subset of `upstream/SECOMP` ([CompCert and SECOMP](../../../THIRD-PARTY.md#compcert-and-secomp)): `lib/`, `common/`, specified `cfrontend/` files, `backend/Cminor.v`, `backend/PrintCminor.ml`, `cparser/`, `export/`, specified architecture files, `extraction/extraction.v`, build files, `flocq/`, `MenhirLib/`, and `runtime/`. Because all verified backend passes, `riscV/`, `cheririscV/`, and `clightgen` (`CLIGHTGEN-LICENSE`, recorded under [VST](../../../THIRD-PARTY.md#vst)) fall outside that dual-licensed subset, Route C yields no resident purecap compiler without commissioning an independent verified backend behind the dual-licensed front end.

## 5. Evidence required for on-device offline self-build

Selecting any route still leaves `M1.10`'s resident admission and offline self-build obligations ([R-13-027](../../spec.md#r-13-027), [R-13-027a](../../spec.md#r-13-027a), [R-08-046](../../spec.md#r-08-046), [R-06-014](../../spec.md#r-06-014)) open until verified on the target composition:

1. **Whole-closure port audit:** Each resident toolchain component is ordinary Tier-2 contained code facing [the porting discipline](../../implementation/userspace-porting.md#the-dependency-closure-is-the-unit-of-work). The audit must clear every `unsafe` site, ambient authority call, and host filesystem, subprocess, or unbounded allocator assumption before porting, starting with the smallest loop-closing checker before the compilers.
2. **Resumable bounded-pool activations (`R-08-046`, `R-13-027a`):** Host builds grow their heap without declared limits; on-device components require declared static pools with explicit capacities, monotone lifecycles, `CapacityExhausted(pool)` refusal actions leaving the running generation intact, step-budgeted (or elastic yield-bounded) resumable passes, and recorded per-pass peaks. In [toolchain residency](../../performance/toolchain-residency.md#8-the-verdict), host `ccomp` (`rv64-linux`) peaks affinely at ~17 MB fixed plus ~182 B per preprocessed byte (`16.5–18.4 MB` on small runtime units and `233.5 MB` on a `1.18 MB` unit), whereas `rocq c` peaks at `283.8–725.7 MB` across 25 of 27 design modules (`1.81x` the `0.4 GB` pessimistic first-class payload floor on `MemoryPlan` alone) and whole-set `rocqchk` peaks at `8.84 GB`. Consequently, the prover/checker working set—not the C compiler alone—binds resident residency across all three routes until resumable bounded-pool passes and [the bounded resident-pass leads](../../performance/toolchain-residency.md#research-leads-for-bounded-resident-passes) close on-target.
3. **Host-vs-device bootstrap comparison (`R-13-027`):** The resident toolchain must compile its own declared closure offline from the device's authenticated store, submit the emitted objects to on-device `CHERI-TAL` and `CIC` admission, and compare receipts with the identical host build—in the locked prover switch `Q39` establishes for Route B, or from the proved definition and reviewed seed under `Q25dk` for Route A. An equal artifact witnesses local reproduction; any mismatch is a defect with its cause named.
4. **De Bruijn root relocation (`R-06-014`):** Neither Route A, Route B, nor Route C eliminates the De Bruijn bootstrap root. All three require inventorying every binary-touching tool in the build ancestry (assemblers, linkers, archivers, strippers, image constructors), executing `DDC` over independently established build paths, and binding the resulting checker bytes to RoT measurement.
