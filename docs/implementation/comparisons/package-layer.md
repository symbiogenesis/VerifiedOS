# Fixed package layer comparison

Status: **open cost comparison**. This artifact evaluates Q31 against the default R-13-028 states and the [alternatives entry](../../background/architectural-alternatives.md#a-fixed-package-layer-with-a-declared-contract-deferred-to-the-comparison-r-13-028-names) records. It selects no layer, amends no entry, and qualifies no external source.

## 1. Baseline and candidate

The baseline is R-13-028 as it stands. A package is content plus its content-addressed source closure, its capability manifest with its interface descriptor, and its proof object (R-13-001, R-13-003). Composing a roster into a generation re-runs whole-image dead and duplication elimination (R-13-010a, R-13-010b), the slot plan (R-08-011) and the schedule (R-11-006) over the whole package closure outside the base image, so every object in that closure is re-emitted with its CHERI-TAL derivation, its source-correspondence theorem and any hyperproperty certificate stated over its bytes; the base image alone is a fixed release object the composition maps and never re-lowers (R-13-026). An install therefore pays the CIC correspondence check over the roster's package closure and not over the package that changed, bounded by R-06-015a's declared budget, and R-17-035a books the consequence: the same act is cheap on a bare device and expensive on a full one.

The candidate is a **fixed package layer**. Each package's code-and-rodata image, data-initializer, correspondence theorem and hyperproperty certificates are emitted once against a declared **package contract** (section 3) and are roster-invariant, as the base image's are. A composition maps such a package rather than re-lowering it, and re-runs only the acts that are the roster's by nature: the slot plan over the packages' declared extents, the schedule over their declared bounds, the capability-wiring table (R-13-006), the handler graph (R-12-024b) and the manifest consistency check. An install then pays the correspondence check over the packages whose fixed objects the store does not already hold as admitted, which on an ordinary install is the package that changed.

What the candidate does not change is stated first, because the proposal is easily read as more than it is. An install is still a generation that takes effect at the next boot (R-13-001a); nothing binds at runtime, no compartment is minted, and no reservation is composed ahead of its occupant (R-13-001b). The composer is still an untrusted producer wherever it runs (R-13-001c), the on-device checks still gate admission (R-13-025, R-11-005), and the per-install source-correspondence check stays on the device, the off-device form being declined at [its own entry](../../background/architectural-alternatives.md#source-correspondence-checked-off-device-leaving-only-the-tal-checker-on-the-install-path-declined). What moves is which objects a composition re-emits, and therefore what an install re-checks.

## 2. What the register decides ahead of any measurement

These readings are decidable from the entries as they stand and bound what the measurement can return.

- **The encoded bytes can be roster-invariant.** R-15-036i makes the dictionary a permanent freeze-time commitment selected once, R-15-036c fixes it as a total function over its entries, and R-15-036b makes decode a pure function of a bundle's contents, so encoding a package under the frozen dictionary yields the same bundles in every roster. Whether the bytes are also *position*-invariant is a separate question, and it is R-15-036l's.
- **The candidate needs the PC-relative arm of R-15-036l inside a package.** A composition-time absolute call or address form is site-invariant only because the image is position-fixed; a package placed per roster has no fixed position, so its intra-package sites take the PC-relative form, which R-15-036k classes as site-varying and which costs the two-slot escape at every such site under R-15-036p's arithmetic. Cross-package edges are unaffected: they are sealed sentry edges reached through the import table and the wiring table (R-05-117, R-13-006), never a displacement. So the candidate's byte cost on this axis is the escape term over the package's own call and materialization sites, and the freeze decision R-15-036l takes decides whether the baseline pays it anyway.
- **Admission splits along the line R-06-008 already draws.** TAL-068 admits no relocatable or symbolically addressed artifact and TAL-067 binds the certificate to a concrete layout, so the CHERI-TAL certificate is re-bound at the roster's layout and re-checked on every install under the candidate exactly as under the baseline. That is the half R-06-015a leaves unbudgeted because its work is linear in the artifact. The half the candidate makes roster-invariant is the CIC correspondence theorem, whose statement is over bytes and whose premises name the wired capabilities the contract declares rather than the addresses a roster assigns. A theorem of that shape is an obligation on M1.2's correspondence route and on the way R-13-006's entries enter it as typed premises; it is not a change to TAL-068.
- **Timing composes by construction here, which is what makes a per-package WCET clause meaningful.** A package's bound is a max-path sum over its own typed control-flow graph against the per-class fetch and access constants (R-11-015, R-15-036e), and the frame is non-work-conserving (R-07-036), so a neighbour's behaviour enters no term of it. The compositional-timing literature names exactly this property as the one most architectures lack (section 8). What the contract must fix for the bound to hold is the memory class of every region the package's code reaches (R-15-247j) and the operating point set the bound is tabulated over (R-11-017).
- **Cross-package colouring already carries a price in the plan.** R-08-012c refuses two confidentiality domains in one granule, and R-08-018a colours pools against each other within one compartment precisely because that case adds no zeroize or revocation term where a cross-compartment colocation would, so a package's live-range colouring is intra-domain today and can be fixed with the package. What the roster plan loses under the candidate is the freedom to choose bank spreading and co-location for the package's internal objects (R-08-012a's second and third terms), which becomes a declared interleave the contract carries and a capacity term the comparison measures.
- **Most of R-13-010b's transforms lose little or nothing across packages.** Outlining and tail merging are intra-compartment by R-15-036o and are untouched. Link-time specialization acts on call sites the frozen graph fixes, and a cross-package edge is a sealed sentry whose callee must receive only its declared entries, so specialization does not cross it. One shared service compartment in place of a per-consumer library is realized under the candidate by packaging the library as its own package with an export world, which is R-13-010b's own preferred form, the immutable object being mapped into each consumer through the wiring table. What remains to measure is identical-function merging across package boundaries, and the exports a package ships that no member of this roster imports, which dead elimination scoped to the contract cannot remove.
- **The log's name does not move, and the image can join it.** R-13-023b computes a package's logged name over what a composition does not touch and excludes the image because R-13-028 re-emits it per roster. Under the candidate the fixed-layer object is one more thing a composition does not touch, so the name may cover it; whether it should is one of the reproducibility duties R-13-028 names, and section 5 states the choice without taking it.
- **Nothing in the candidate is the empty slot R-13-001b forbids.** A contract fixes a package's extents, bounds and edges; it composes no reservation ahead of an occupant, and a roster that cannot meet a contract fails composition rather than admission, which is R-17-033's polarity as R-13-001c already applies it.

## 5. The pack, the store, the log and the step rule

**The pack gains one object kind and no grammar.** The fixed-layer object is the image, the initializer, the correspondence theorem, the hyperproperty certificates and the derivation's non-binding parts, named by the content hash of the tuple (source-closure name, manifest-and-descriptor hash, contract hash, certificate-header versions). It is a content-addressed object like every other (R-13-007), decoded by the same copy-once reader over the same fixed-layout format (R-13-009), and it lives loose and deduplicated in the store. A publisher may ship it inside the pack beside the closure, and R-13-008's set difference then moves it once per device. Under the baseline no fetch can share an image, because the composer emits one per roster; under the candidate the expensive producer act, the correspondence proof, is done once per package rather than once per device per install.

**The store and the composition mode.** What a device composes locally shrinks to the roster-level acts of section 6, so the composition mode R-13-027a declares is entered for a smaller act; its pools and step budgets are unchanged in kind. R-13-027's obligation that every generation the device runs it can also produce is unchanged: the device holds the closure and the toolchain, so it can emit a fixed-layer object itself, and an object it emits is admitted exactly as a fetched one (R-13-013). R-02-008 is unchanged for the same reason: a fixed-layer object is data in the store until a successor generation admits it.

**The logged name.** R-13-023b's name is computed over the source closure and the manifest hash. The candidate makes the image a roster-independent function of those two, the contract and the versions, so the name may include the fixed-layer object's hash. Including it makes the log commit to bytes and not only to source, which is a stronger public commitment; it also makes two honest builds of one closure carry two names unless the fixed-layer object is reproducible, which R-13-026 requires of the base image and the checker binaries and of nothing else. That is the reproducibility duty R-13-028 names, and the arms are: keep the name over closure and manifest and log the object hash as a second, optional commitment; or require reproducibility of fixed-layer objects and extend R-13-026's DDC scope to them. The comparison records the arms; a register act takes one.

**The step rule.** R-11-005b already makes every descriptor the trust base reads across a generation boundary carry its version and makes a successor's proofs stated against the installing generation's spec-set and model versions. A fixed-layer object carries those versions in its certificate header, so it is installable by a generation whose reader installs its descriptor version and whose spec-set it was proved against, and a rev of either is a new object, as R-11-005 already requires re-admission on a rev. Nothing a device several steps behind does changes.

## 6. The composer and the install path under the candidate

**Package construction**, wherever it runs (R-13-001c): compile the closure to the frozen profile under the contract; run dead elimination against the contract's roots; run the intra-compartment outlining and tail merging of R-15-036o; link with the PC-relative forms inside the package; encode under the frozen dictionary; emit the image, the initializer, the derivation template, the correspondence theorem over the bytes with the contract's wired capabilities as premises, and the hyperproperty certificates per class assignment and operating point; hash and, where a publisher supplies it, log the name.

**Composition**, over a roster: map the base image and every fixed-layer object; check each package's imports against the roster's exports and labels; place every package's declared extents by the plan's objective (R-08-012a) at the class each region declares; build the wiring table; emit the admission artifact; compile the handler graph; re-bind each package's derivation at its layout; sign the root.

**Install**: hash-verify every object; type-check every re-bound derivation; CIC-check the correspondence theorem and hyperproperty certificates of every fixed-layer object the store does not already hold as admitted, under R-06-015a's budget; check slot disjointness, initialization and temporal safety over the roster's plan in the one pass R-08-014 names; check the wiring table's monotonic derivation; wire; commit through the transactor.

What that buys the person holding the device is stated so it can be measured. An install's proof cost tracks the change and not the roster. A package fetched with its fixed-layer object arrives proved, and what the device proves is the roster. The composition mode is occupied by the roster-level acts alone. What it does not buy: a boot is still paid (R-13-001a), a running generation is still never edited, and a fetched proof is still checked and never trusted.

## 9. What this comparison does not decide

It selects no layer: R-13-028's default stands until Q31 runs the predicate of section 7 against the artifacts it names. It amends R-15-036l in neither direction: the freeze decides the call form, and the candidate's byte cost on that axis follows from the decision rather than steering it. It does not move TAL-068: the derivation is re-bound and re-checked per roster under both sides, and the roster-invariant half is the CIC theorem alone. And it makes no new normative claim: every clause of section 3 names the entry that owns it, and a package contract entered into the register would collect those owners rather than restate them.
