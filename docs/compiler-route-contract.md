# Compiler route comparison contract

Q21b's deliverable is a reviewed comparison at one artifact boundary: capability-correct final bytes, their required TAL and CIC evidence, and correspondence to the exact operational source. This document specifies that comparison for CHERI-C/Clight and direct capability-aware lowering. It supplies neither a compiler implementation nor a route selection. The [implementation checklist](implementation-checklist.md#q-assessment-actions) owns scope, estimates and execution state; the [strategy](verification-language-strategy.md#compiler-route-decision) owns the architectural alternatives.

**Review state: candidate contract; executable trial unopened.** The source boundary is shared with [Q21a's core design](language-core-design.md), the existing-route dependencies with [Q2c's foundation map](cheri-foundation-map.md), and the accounting and target protocol with [Q20a's workflow contract](language-workflow-contract.md). The [pricing and entry conditions](#pricing-and-entry-conditions) identify the unresolved join. Missing establishment estimates and missing proofs prevent acceptance as a costed executable trial; they are not evidence that either route loses.

## Fixed consumers and common source boundary

The initial client is a descriptor parser with copy-once initialization into a caller-provided fixed destination, followed by use of that initialized result. The required positive case has a bounded input view, checked field reads, an explicit failure result, no allocation, and a destination predicate established on success. Its operational contract retains the declared behavior on every failure exit, including which destination fields are initialized and which authority is returned. A partially written destination cannot acquire a fully initialized type by returning an error.

The current [DescriptorCheck](../tools/bedrock2-lowering/DescriptorCheck.v) is the starting executable specification for the header check. It reads and checks; it does not copy a descriptor or initialize a destination. The additional realization is a missing producer input whose owner and estimate must be settled under Q2c/Q2b before the initial client exists. Neither its hand-written C yardstick nor an unproved printer becomes the required decoder implementation under R-05-043.

The reserved client is copy-service staging under [CopyRingService.v](../proofs/CopyRingService.v), restricted to the copy-once and bounded staging portion of M7.1. It validates the length of a stable source image, copies the accepted prefix into an already initialized fixed private destination while preserving its suffix, and uses that staged image despite a different subsequently supplied source image. Refusal preserves the destination and reads no source bytes. The surrounding ring, scheduler, DMA service and concurrent service implementation are outside this trial. The [workflow contract's clients](language-workflow-contract.md#clients-and-baseline-evidence) fix the fuller protocol; expanding it requires a new trial revision.

The reserved client's public contract identifies the intended workload; its implementation and adaptation supply no interface-design feedback before the initial client's interface, emission rules and proofs are frozen. Reading its contract does not permit tailoring a rule to make that reserved adaptation pass. If the reserved client is used to redesign the interface or emission family, it becomes a development client and the trial needs a fresh independently selected consumer under Q20a's reviewed protocol. A different lane implements the reserved adaptation against the frozen interface, and cannot silently fit new constructs to it.

Both routes consume Q21a's same content-addressed `SourcePackage`, interpreted computation and representation contract. That contract exposes an explicitly sequenced operation graph, stable runtime indices, erased checked evidence, branch-specific resource predicates, bounded loops, a closed read/write/call/no-allocation effect summary, and a fixed layout and ABI instance. Inputs, outputs, I/O observations, prescribed refusals and faults, and the leakage and cost observations required by the assurance tier remain part of the meaning. A direct CFG, block or SSA representation is an internal choice with a checked relation to that graph, not another authoritative source.

The matching manual baseline implements that same contract and obtains the same evidence endpoint. It is independently maintained only as the experimental comparator. The generated unoptimized and optimized variants each regenerate from the authoritative source. Each route gets the same source change, input set, caller grants, primitive contracts, memory placement, link context, optimization eligibility and evidence obligations. A route cannot buy an apparent saving by assigning its caller a larger grant or weakening the failure predicate.

## Equivalent artifact endpoint

An endpoint package contains the authored source closure, elaboration and interpretation evidence, representation instance, generated IR, transformation records, exact primitive and ABI contracts, final linked image and its digest, TAL certificate, deeper CIC proofs required by its tier, and the validation record for every assembly, relaxation, link, layout and image-construction step. Every machine theorem resolves to the same Sail-generated Rocq definitions used by hardware refinement under R-05-019b. A proof of a separately transcribed capability machine is an unconnected result until an admitted agreement theorem supplies the connection.

The final-image source-correspondence theorem quantifies over every behavior permitted by the selected model and context and refines the exact committed source closure under its explicit assumptions. It covers failures, divergence or termination as the contract requires, authority and initialization effects, and declared observations. A terminating postcondition alone does not supply progress. Robust preservation additionally quantifies over adversarial linked contexts under R-05-024; an induction on emitted programs or tests of selected hostile callers does not replace that quantifier.

R-05-023a still requires CIC-checked decompilation into the R-13-017 Iris-over-Sail logic. Unary safety, the universal capability contract, relational constant-time and syntax-directed cost remain theories of that logic. TAL soundness and the required deeper proof obligations meet the final binary under R-05-026. A bounded emission theorem can assist construction or discharge instruction cases in that logic; it cannot make that logic unnecessary by restricting the producer's syntax. Host SMT, oracle and differential results can falsify claims and cannot act as substitute kernels.

For each route, validation and target execution consume that route's exact final image; promotion retains those bytes. The two routes need not emit identical bytes. Their theorems must relate their respective bytes to the same source contract, assumptions and observation model. A changed relocation, byte, certificate, source binding or configuration invalidates the dependent evidence. Recompiling after validation produces a new subject and requires a new package.

## Route boundaries and closed emission family

**Clight arm.** Construct an imperative implementation with a proved relation to the common source graph, prove the representation bridge to capability-aware CHERI-C/Clight, retain the applicable verified compiler passes and their proofs after the CHERI adaptation, then supply final Sail validation and admission evidence. C printing is included in the bridge if used. Retaining invariants in simulation relations is allowed; erasing an annotation does not waive proving its semantic consequence.

**Direct arm.** Construct an explicit-memory capability IR with a proved relation to the same source graph and representation, compose the bounded emission rules below, and reuse or verify/validate applicable optimization and allocation before the same final Sail and admission endpoint. A block representation is the trial's default interface because sequencing and joins are explicit; introducing SSA requires a proved conversion, phi/parallel-move behavior and capability-preserving allocation, charged to the direct arm. No general frontend, LLVM path or new optimization framework is commissioned here.

The candidate family below is a proposed closed producer grammar. It is not a second enumeration of the ISA: concrete encodings and primitive names are resolved exclusively through the selected [profile](isa-profile.md) and its Sail clauses under R-05-023b. Each rule record binds its input constructor, emitted term, entry and exit representation predicates, consumed and restored frame, word-arithmetic premises, effects and observations, termination/cost obligations, and the Rocq constant of its Sail simulation. An empty constant field blocks the rule; a comment naming a desired theorem does not fill it.

| Rule family | Permitted form | Required proof obligations and refusing neighbor |
| --- | --- | --- |
| `value` | Fixed-width scalar constants, comparisons, arithmetic and explicit extension/truncation; structured initialized values | Checked ranges or modular meaning, field layout and observable result. Pointer/integer reinterpretation cannot be hidden in a cast. |
| `read` | A bounded byte or declared scalar read through a live read capability | Tag, provenance, permissions, range, alignment and initialization; frame preserved. Moving a load before its admitting guard is refused. |
| `write` | A declared field or byte write through exclusive fixed-destination authority | Exact initialized-range transition, no padding read, no overlapping live writer; failure exits retain their actual partial state. |
| `capability` | Tag-preserving moves and stores/reloads, bounded advance, permission attenuation and exactly representable narrowing | No authority creation, correct tags and representability, declared pointer width/register organization, and the same trap behavior as Sail. Integer spill/reload and outward-rounded bounds are refused. |
| `sequence` | Explicit left-to-right composition and pure local bindings | Intermediate predicates match, frames compose, runtime uses remain legal after erasure; duplicating affine authority is refused. |
| `branch` | Boolean branch or closed discriminant case with explicit result/resource joins | Every ordinary and failure exit restores the declared resources; secret observations obey the selected relational contract. Missing failure restoration is refused. |
| `loop` | A bounded loop with a declared invariant and ranking/bound evidence | Initialization, preservation and exit, finite bound, accumulated effects and cost, consistent loan restoration on every iteration. No data-dependent unbounded loop or implicit allocation is admitted. |
| `frame` | Static entry/exit and declared spill slots under the composed plan | Fresh initialized live ranges, tag-preserving spills, stack bounds, preserved registers and exact return authority. No runtime allocator, garbage collector or hidden dynamic frame exists. |
| `call` | A statically linked helper or explicitly contracted sentry/primitive call with the matching return form | Required/provided ABI and authority, effects, observations, relocations and termination behavior; no unchecked external, callback, suspension or reentrancy is added. Primitive semantics is its profile-bound Sail clause. |

The trials use scalar operations required by the selected clients. Q20a's repeatable zero-byte source callback must specialize to a proved loop body or statically contracted helper before entering this family; specialization preserves its invocation, capture, effect and restoration obligations. The family admits no unchecked dynamic callback. This restriction does not discharge R-18-014's vector, scalar-floating-point or other production completeness duties. A bounded success qualifies the family and clients only. M1.3 and M1.3a remain the owners of applicable required optimizations, including outlining and tail merging; they do not acquire a second budget here.

Closure is decided in the following order, with the rules and proof constants frozen before the reserved client is lowered:

1. Generate the constructor census from the initial source graph and from every intermediate after erasure, lowering, optimization, allocation and linkage. Every reachable construct, helper and linker-created stub resolves to one rule and one checked contract. Unknown constructs fail with a source/site identifier.
2. Prove the generic composition theorem over all programs of the admitted family, including loop invariants, branches and failures. Compose it with the source interpretation and the Sail connection, then inspect its assumptions. Enumerating example programs alone cannot satisfy this step.
3. Lower the reserved staging client with the unchanged grammar, definitions and proof constants. New instances and checked client invariants are permitted and counted; a new semantic constructor, representation exception, special-case rule or stronger caller assumption fails this closure trial. Report the missing rule instead of expanding the test population after observing it.
4. Decode the final image and check total site coverage, primitive meanings, typed linkage, relaxation preconditions and artifact identity through the required existing validation path. A producer census that ignores linker-introduced code fails.
5. Run the mutations below against their intended judging layer and the exact artifacts. Separate compile-failing stillborn mutations from those that reach a semantic or admission judgment. A survivor is an unresolved finding, not part of the passing denominator.

Baseline source identities in [the evidence table](#baseline-identity-and-evidence) remain fixed historical comparators. New producer revisions are named and frozen in this manifest by their owners before paired measurements, not filled with a guessed future commit. Replacing a baseline or threshold after seeing results is a revised experiment with an explicit reason; the old result remains visible. The compiler binary, runtime/primitive closure and copied third-party preambles enter identity and licence accounting alongside authored source.

Use [Q20a's target protocol](language-workflow-contract.md#target-and-production-artifact-protocol): identical actual profile and Sail closure, memory-class and slot assignments, ABI and calling context, generation constants, link policy and eligible transformations. The main comparison includes manual, generated unoptimized and generated optimized variants at the same assurance endpoint. A secondary unoptimized comparison may isolate construction overhead; it earns no production performance claim. Every method receives the same initial, empty, one-element, boundary and full-capacity inputs, malformed discriminants, truncated fields, overflow and failure cases, with limits generated from the frozen declarations.

No missing metric is inferred from another unit. The corpus trace exposes architectural retire order and capability memory effects; it does not supply a cycle counter. A timing claim needs the selected timing annotation and its declared core class, obtained under R-18-024/R-18-025, or a separately identified instrument with its justified model. Host elapsed time is proof/build cost; instruction count is code/trace evidence; neither is target cycles or a WCET certificate. SRAM/interconnect traffic and tag effects are reported from supported observations, never as invented cache misses or silicon stalls.

Capability-specific attribution records actual narrowing/derivation and redundant authority operations, tag-preserving spill/reload traffic, peak live capability pressure, ABI and slot padding, representability refusals and the interactions of allocation or memory promotion with tags. A scalar transformation is not charged as a capability saving merely because its operand occupies the merged register file. Report where provenance-preserving CSE, coalescing or allocation reuses existing qualified machinery, where a new proof is required, and the source/site responsible for each cost. Read the width and register organization from the selected profile and model instead of assuming a separate capability file or an upstream pointer size.

## Negative and disagreement cases

The population is generated from the selected declarations and emitted sites. Each family below has an intended failure layer recorded before mutation; a syntax error is not the claimed semantic refutation. Source-level neighbors may properly fail elaboration, while backend and artifact mutations must reach the downstream judgment whose coverage they test.

| Mutation or disagreement | Required outcome |
| --- | --- |
| Swap equal-width direction/content fields while leaving total size unchanged | The descriptor-layout/source correspondence judgment rejects the changed interpretation. Existing arithmetic reflexivity checks and unchanged emitted bytes alone do not catch Q2a's recorded field-order gap. |
| Move a read before its length guard; truncate the destination; claim an untouched field initialized | Construction or representation proof fails at that access/exit, or final evidence refuses the resulting image. No error status excuses an out-of-bounds read. |
| Convert a capability through an integer, strip a spill tag, broaden a bound or increase permissions | Representation/emission or final Sail/TAL evidence fails even if the low data bits and a host test result agree. |
| Duplicate a live writable loan or omit restoration on failure, loop exit or return | Source resource checking or the binary/frame proof refuses it. Exempting an exit is a changed contract, not a passing mutation. |
| Re-read the source after validation in the staging client | The copy-once/source-stability claim is refuted using distinct first and second images. It is not implemented as a concurrently racing read of a live writable non-atomic buffer. |
| Add a secret-dependent address/branch or an invalid variable-latency operation during optimization | The applicable relational leakage judgment fails even if functional outputs agree. |
| Introduce an unlisted helper/stub, change a sentry role or preserve the wrong register set | Closed emission coverage or typed linkage fails. No unmodeled external-call assumption is appended to rescue the image. |
| Change source resolution/desugaring, a dependency or the representation while reusing an old core proof | `SourcePackage` or a dependent evidence binding is invalidated; a valid theorem about the old core cannot certify the new source. |
| Alter bytes, relocation, composed layout, TAL evidence or primitive mapping after validation | The package fails identity, coverage, typing or refinement at the affected boundary. Independently rebuilding another image does not repair this one. |
| The two routes return different statuses, effects, tags, failures, resource use or allowed observations | Preserve both images and reduce the disagreement against the common source contract and pinned Sail definitions. No route serves as truth merely because it is incumbent or shorter. |
| Both routes agree but the reference contract is weakened or common parsing/layout is wrong | The negative contract cases must still reject; shared parsers, source generation, semantics, proof kernel and validation infrastructure are recorded as common-mode dependencies. Agreement is not independent proof. |

Source maintenance probes separately change a client bound, an equal-width field interpretation, the representation or ABI, and an admitted optimization choice. Record which generic theorems replay unchanged, which instance and client proofs change, which certificates invalidate, and the attended repair plus machine costs. The reserved client cannot count a newly authored byte semantics as generic reuse.
