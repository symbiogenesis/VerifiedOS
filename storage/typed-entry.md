# Bounded typed storage entries

The numeric `VOSNODE1` codec is a bring-up index instance. It cannot encode
[the L2 tuple](../proofs/KeyspaceDomains.v#K2) or an authenticated extent in one
64-bit value. The bounded typed codec uses the tuple's actual
[lexicographic order](../proofs/KeyspaceDomains.v#ksig): domain, namespace,
kind, object, attribute, version. Snapshot selection first selects a retained
root; version order within that root does not require scanning every snapshot.

For this C instance each component is an unsigned 64-bit integer. Its key is
exactly six big-endian words, so unsigned byte comparison preserves the tuple
order without truncation, hashing or an indirection. The general Gallina naturals
need an explicit fitting proof before conversion into this bounded instance.

`VOSEXT01` is a 96-byte extent descriptor: magic (8 bytes), physical block
address, byte length, nonce node identity and generation (four little-endian
64-bit words), domain epoch and kind (two little-endian 32-bit words), the full
16-byte AES-GCM tag, then the independent 32-byte keyed content digest. Nonce
coordinates must fit the existing canonical node-nonce codec. Address and length
must additionally fit the selected medium and extent at integration; this codec
does not authorize IO, authenticate a tag or establish content freshness.

A typed leaf entry occupies the key and whole descriptor inline. Its admission
computes capacity from the selected block/header sizes and refuses a block that
cannot hold one entry. The numeric 128-byte node instance therefore cannot be
silently reused for typed leaves. Authenticated publication, production
composition, C/Gallina refinement and target execution remain M5.3d/M5.4 joins.

## Typed node and routing contract

The bounded executable M5.3d boundary stores the complete key and extent inline in
typed leaves. `VOSTYP01` nodes use the numeric codec's 32-byte header layout:
magic, little-endian 32-bit kind and count, then little-endian 64-bit node
identity and generation. A leaf stores `count` consecutive 144-byte entries
(48-byte key followed by its complete 96-byte extent); a branch stores
`count - 1` complete keys followed by `count` little-endian 64-bit child
identities. Padding is canonical zero. The selected geometry must fit a full
leaf at its declared fanout, between two and sixteen. Numeric node bytes and
the undersized numeric block geometry refuse rather than convert implicitly.

Input and output objects must be disjoint; inputs remain unchanged during each call.
Encoding and decoding validate local shape, identity, generation, references,
extent coordinates and padding before changing caller output. They preserve
all six key components and every authentication byte. They do not authenticate
blocks, establish physical extent bounds or select a production geometry.

Full-tree lookup admits strict lexicographic leaf/separator order, inherited
half-open key ranges, exact declared leaf depth and finite depth/visit bounds
over stable caller-authenticated blocks and independently bound generations.
It returns an extent only after every reachable branch is admitted. Path lookup
checks the same conditions on the selected root-to-leaf path; an unvisited
subtree is not admitted by that operation. A true miss and structural refusal
are distinct and both preserve output. Expected generations come from independent
retained-root evidence, never the untrusted block's own identity fields. Repeated
references to an empty subtree are permitted when each inherited interval admits
it, following [the reference's well-formed predicate](../proofs/ExecutableIndex.v#well_formed);
each reference consumes a visit. This interface adds no unique-parent condition.
A cyclic reference cannot outlive the
declared finite depth. Empty leaves and single-child branches retain the
reference's admitted local shapes.

Acceptance requires independently generated canonical bytes and tuple-order
expectations across every key component and full-width boundaries, exact extent
metadata on found results, retained-root/generation controls and positive misses.
Malformed ordering, ranges, references, depth, padding, generations and work
limits refuse without output changes. Compiled routing and admission defects
must compile, execute and fail their specified assertions. Focused native C
checks supply this bounded codec/read evidence. Authenticated publication,
C/Gallina refinement and purecap target execution remain open. The production
Narcissus grammar/canonicity, branch authentication metadata and parametric
correspondence remain governed by
[the production typed-key contract](tree-image.md#production-typed-keys-and-authenticated-values).

The codec passes when independent generated byte vectors round-trip complete
full-width tuples and descriptors; byte comparison agrees with tuple order,
including namespace/kind and 64-bit boundaries; malformed lengths, magic and
nonce coordinates refuse without output changes; and fitted geometry includes
every inline metadata byte. Native regression and executed malformed inputs are
focused checks, with hosted acceptance retained by the shared handoff.

## Bounded typed candidate insert and replace

The [typed update interface](include/vos_typed_tree.h) follows the append-only
[candidate contract](tree-update.md) for single-key insertion and replacement.
The caller supplies the full-capacity arena and expected-generation array, their exact
lengths and the nonempty allocated prefix. The caller authenticates the
retained bytes and generation evidence and keeps them stable. The backing
arrays, key, extent and result are disjoint. Before appending, full admission
checks every reachable reference against the allocated prefix, including
off-route nodes, and the existing extent codec checks the new descriptor.

The candidate inserts the complete key in lexicographic order or replaces the
complete extent at an equal key. Separator equality routes right. The update
copies only its path into the unused suffix and preserves all other subtree
identities and generations. Leaf overflow promotes the first key of the right
half. Branch overflow promotes the separator immediately before the right
half. Both divide at half the overflowing entry or child count. A root split
creates a new branch and increases the exact leaf height once. Every appended
node uses the caller's candidate generation.

Success requires full candidate admission within the returned prefix and a
lookup of the exact key and complete encoded extent. The prior and candidate
walks each obey the same visit bound. A root split obeys the declared depth
bound, and append operations cannot exceed capacity. The retained byte and
generation prefixes remain unchanged on every result. Only success returns a
new root, height and allocated length. A refusal can leave suffix bytes and
generation cells to be overwritten by a later attempt without consuming the
allocated prefix.

Focused native acceptance compares independently generated tuple-to-extent
maps and canonical node bytes, including full-width keys, equality replacement,
leaf, branch and root splits, unchanged sibling references and retained roots
with mixed generations. Allocation, depth and candidate visit exhaustion,
invalid descriptors, and a reachable off-route reference into the unallocated
suffix refuse while preserving the retained prefixes and result. Compiled
update defects must execute and fail their designated assertions. Authentication,
durable publication, C/Gallina refinement and two-instance target acceptance
remain governed by M5.3d's existing joins.

## Bounded typed candidate delete

`vos_typed_tree_delete` in [the typed update interface](include/vos_typed_tree.h)
implements Rodeh-style lazy copy-on-write deletion without sibling underflow
borrows or merges, matching [the numeric deletion contract](tree-update.md).
The caller supplies the full-capacity arena and expected-generation array,
their exact lengths, the nonempty allocated prefix `used`, and stable
caller-authenticated retained blocks and generations. All backing arrays, key
and result objects must be disjoint.

Before any suffix write, full prior-tree admission via `vos_typed_tree_lookup`
checks every reachable reference against the allocated prefix, including
off-route subtrees. Both structural refusal (`VOS_TREE_REFUSED`) and a missing
key (`VOS_TREE_MISSING`) refuse (`0`) with zero suffix writes and unchanged
output.

When the key is found, deletion rewrites only its root-to-leaf path into the
unused suffix using the caller's `generation` and removes the matching entry
from its leaf. If a leaf becomes empty, it is pruned from its parent branch,
shifting surviving children left and dropping `keys[0]` when `route == 0` or
`keys[route - 1]` when `route > 0`; if a branch loses its last child
(`count <= 1`), emptiness propagates upward without appending dead nodes. When
the entire tree becomes empty, deletion allocates an empty `VOS_NODE_LEAF`
(`count = 0`) at height `0` in `generation`. Otherwise it collapses single-child
branch roots (`kind == VOS_NODE_BRANCH && count == 1`) while `height > 0`, and
copies any surviving retained node (`< arena->used`) into the suffix in
`generation` so every accepted delete yields `used > arena->used`,
`root == used - 1`, and preserves retained-root generation isolation without
leaving unreachable appended nodes.

Success requires full candidate admission via `vos_typed_tree_lookup` at the
candidate height returning `VOS_TREE_MISSING` within `limits->visit_limit`
before updating `output`. Retained byte and generation prefixes remain
unchanged on every result.

Focused native acceptance checks missing-key refusals (`staged=False`),
exact byte-for-byte non-empty leaf shrinks, empty-leaf pruning at `route == 0`
and `route > 0`, multi-level single-child root collapse (`height 2 -> 1 -> 0`),
final deletion to an empty leaf root at height `0`, retained-root lookups with
original extents and mixed generations, bounded allocation/visit exhaustion,
off-route suffix-reference refusals (`staged=False`), generated full-width
6-word key sequences deleted in ascending, descending and interleaved orders
across fanouts `2`, `3`, `4` and `16`, and compiled behavioral mutation controls.

## Bounded typed candidate batch insert

`vos_typed_tree_insert_batch` in [the typed update interface](include/vos_typed_tree.h)
applies a strictly key-sorted batch of `1..VOS_TREE_MAX_BATCH` `(key, extent)`
entries in a single top-down copy-on-write pass over `VOSTYP01` nodes, matching
[the numeric batch contract](tree-update.md). The caller supplies the
full-capacity arena and expected-generation array, their exact lengths, the
nonempty allocated prefix `used`, and stable caller-authenticated retained
blocks and generations. Backing arrays, entries, and result objects must be
disjoint.

Before any suffix write, admission validates the arena and limits,
`1 <= entry_count <= VOS_TREE_MAX_BATCH`, strictly increasing 6-word keys,
valid `VOSEXT01` encoding for every batch extent, and full prior-tree admission
via `vos_typed_tree_lookup` on `entries[0].key` within `limits->visit_limit`.
Empty, unsorted, duplicate-key, oversized, invalid-extent, or structurally
malformed inputs (including reachable off-route suffix references) refuse (`0`)
with zero suffix writes and unchanged `output`.

When admitted, the update partitions the sorted batch across branch separator
intervals so untouched sibling subtrees are neither decoded nor copied and each
modified subtree is allocated in `generation` at most once per batch. Leaf merges
replace equal keys and insert missing keys in lexicographic order. Overflowing
nodes split via balanced chunking into nodes of at most `fan` items (halving
the trailing remainder when `fan < rem <= 2 * fan`) within bounded per-frame
staging (`VOS_TYPED_BATCH_MAX_ITEMS = VOS_NODE_MAX_FAN + VOS_TREE_MAX_BATCH + 2`),
and multi-level root growth allocates new branches up to `limits->depth_limit`.

Success requires full candidate admission via `vos_typed_tree_lookup` on
`entries[0].key` and `vos_typed_tree_lookup_path` on `entries[1..entry_count-1]`
within `limits->visit_limit`, verifying exact 96-byte encoded extent equality
for every batch entry before updating `output`. Retained byte and generation
prefixes remain unchanged on every result; capacity, depth, or candidate visit
exhaustion refuses while preserving retained prefixes and `output`.

## Bounded typed candidate compact

`vos_typed_tree_compact` in [the typed update interface](include/vos_typed_tree.h)
packs all reachable live `(key, extent)` pairs of a valid `VOSTYP01` tree into a
canonical, history-independent B+ tree in `generation`, matching
[the numeric compaction contract](tree-update.md). The caller supplies the
full-capacity arena, expected-generation array, nonempty allocated prefix
`used`, and stable caller-authenticated retained blocks and generations, with
disjoint backing arrays and result.

Before any suffix write, admission validates the arena, limits, and full
prior-tree admission via `vos_typed_tree_lookup` with a zero key within
`limits->visit_limit`, together with bounded prior entry counting. Structurally
malformed trees and off-route suffix references refuse (`0`) with zero suffix
writes and unchanged `output`.

Compaction traverses reachable leaves in sorted lexicographic order and packs
all live `(key, extent)` pairs bottom-up into new `VOSTYP01` nodes in
`generation`, filling leaves and branches to `fan` except along the right spine
and promoting each child's minimum key as branch separator. An empty tree emits
one empty `VOS_NODE_LEAF` (`count = 0`) at height `0`; single-child top
branches collapse so any two valid trees with the same `(key, extent)` map and
geometry compact to byte-identical node layouts regardless of prior insertion
or deletion order.

Success requires full candidate admission via `vos_typed_tree_lookup`
returning `!= VOS_TREE_REFUSED` within `limits->visit_limit` and an exact live
entry-count match against the prior tree before updating `output`. Retained byte
and generation prefixes remain unchanged on every result; arena capacity or
depth exhaustion refuses while preserving retained prefixes and `output`.
