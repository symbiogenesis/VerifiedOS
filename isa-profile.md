# The Frozen Instruction-Set Profile

*Normative as a **view**. This document is the artifact **R-15-001a** mandates and R-15-001, R-15-014, and R-18-003a depend on: the single enumeration of the frozen profile. It is **derived from** [requirements-register.md](requirements-register.md), which remains the audited artifact per R-05-152.*

> **Precedence.** Where this document and the register disagree, **the register wins and this document is defective.** Every row cites the requirement that governs it, so a disagreement is a locatable defect rather than an ambiguity. This document adds no obligation of its own; it collects obligations stated elsewhere.

## Why this document exists

R-15-001's acceptance criterion reads *"the frozen profile enumerates exactly this extension set."* Without this document there is no such enumeration: the profile would be an emergent property of some seventy requirements spread across §15.1–§15.12 and §15.16, and the criterion would name an artifact a reviewer cannot open. Four criteria test membership in the profile this way (R-15-014, R-15-024, R-15-042, R-15-067), so all four are decidable only against this document.

It matters beyond review hygiene. R-18-003a makes the profile freeze the **root of the schedule** (the toolchain, the Sail model, and the CHERI-CompCert backend all target it, so it precedes all three), and R-18-003b(i) makes *"the provisional profile freeze and its Sail curation"* the first day-one deliverable, that being the first of the freeze's two acts (§11, R-15-014a). This is the document that deliverable consumes: what a Sail curator removes from `sail-riscv` ⋈ `sail-cheri-riscv`, and what the backend's target description must match.

**Ztso is the specified model, and sequential consistency is not a pending change.** SC was evaluated and rejected on four platform-specific grounds, none of which has a hart-count or issue-width term: single-copy memory keeps the deviation from SC local to each hart's store buffer (R-15-087), so the rejection holds at any core count and gets *stronger* with width; §18 names it as a question worth revisiting, which is a question and not a deliverable (R-15-018). A curator implements Ztso.

**No runtime CHERI disable.** `misa` is read-only (R-15-052), so the CHERI extension bit cannot be cleared, and what that refuses here is not an ISA-configuration nicety but a software-reachable switch that turns off every memory-protection mechanism the machine has. The standards line makes the switch concrete: RVY's `misa.Y` resets to 1 and clearing it disables CHERI entirely, gated only by a check that `pc`, `xtvec`, and `xepc` hold root capabilities. Here it is refused three times over. `misa` is read-only, so no write reaches the bit (R-15-052). The platform is purecap-only, with no non-CHERI host, no plain-RV64 target, and no capability-degraded state to morph into, so a CHERI-off hart has no defined execution rather than a degraded one (R-15-001, R-18-002). And CHERI is the sole memory-protection mechanism, PMP deliberately forgone, so the switch would not change the protection regime but delete it (R-15-075, R-15-076). "No runtime ISA morphing" and "no runtime CHERI disable" are the same sentence on this platform. The enable-side half is §5.2: there is no enable bit to set either.

### 1.1 The instruction encoding

Code is resident, fetched, and decoded in one fixed-rate **dictionary format**. It is a fetch container below the instruction level, not an extension: it allocates no opcode, adds no instruction, and changes no semantics.

| Field | Reference value | Note | Governing |
| --- | --- | --- | --- |
| bundle | 128 bits | bundle-aligned, fixed latency, flat SRAM; a DSE parameter frozen with the profile | R-15-036a, R-15-036e |
| header | 16 bits | one escape-start bit per slot; remaining bits reserved and **trapping** | R-15-036a, R-15-014 |
| slots | 7 × 16 bits | each an index into the immutable dictionary, or part of an escape | R-15-036a |
| escape | exactly 2 slots | one canonical 32-bit instruction verbatim; **may not straddle a bundle boundary**, and is **not** pair-aligned within one | R-15-036a, R-15-036b, R-15-036j |
| dictionary | ≤ 2^16 entries, realized size frozen | complete canonical instructions, **immediate included**; indices above the realized size **trap** | R-15-036a, R-15-014, R-15-036k |
| padding | 1 slot, where an escape will not fit | the format's reserved `nop` index, allocated by the format rather than selected; sequential decode reaches it, so it executes rather than traps | R-15-036j, R-15-014 |

**Four consequences a curator should not have to re-derive.**

- **Decode is a function of (bundle, slot index), not of decode history.** Entering a bundle at slot *k* yields exactly what a linear decode yields from slot *k*, so mid-instruction reinterpretation has no representation rather than being argued away. There is no carried fragment, no alignment buffer, and no decoder state (R-15-036b). This is what the `C` exclusion was protecting, obtained more cheaply than `C` could have given it back.
- **The proof obligation is bounded at the decoder.** The dictionary is a total `Fin N → Instr` into the already-admitted instruction type, so `∀ i, exec(dict i) ≡ exec(canonical i)` discharges by reflection over N constant entries and no obligation above the decoder moves (R-15-036c).
- **Two obligations do move, and both are composition-time.** Control-flow targets are slot-aligned and escapes are bundle-contained, enforced by the encoder (R-15-036b); and constant-time balancing of secret-dependent arms is stated over **encoded bundle count** rather than instruction count, since equal instruction counts can differ in escape density (R-15-036f).
- **The scope line is normative.** The encoder is composition-time only, the resident decoder is hardware, the encoding reaches nothing but immutable code, and no secret may be a composition-time input to an encoded image, so link-time specialization may not specialize on a confidential value (R-15-036g). The filesystem-compression exclusion (R-10-018) and the no-memory-path-cryptography rule (R-15-199) are untouched.

**Density is a model, not a quotation, and it has two terms.** The slot term is 36.6 − 18.3*p* bits per instruction for dictionary hit rate *p* (R-15-036h); the packing term λ charges the slots escape packing strands, since an escape is two slots in an odd-slot bundle and a bundle at one free slot must be closed with a padding slot (R-15-036j). Together they give **60–70%** of the canonical stream at *p* between 0.95 and 0.80, against the 70–75% `C` would give. The low end is break-even, not a win: break-even against the optimistic `C` figure is *p* = 0.804 and against the pessimistic one *p* = 0.728, so the density claim is a claim about *p* and it is false below 0.804.

**Which makes *p* a stratified measurement, not a number.** A dictionary entry is a complete canonical instruction *including its immediate*, so site-invariant operands hit and **site-varying** ones miss by construction: the `auipcc` + `cincoffset` materialization pair, `cjal`, and forward branches carry PC-relative displacements that differ at every site. *p* is measured with that class counted separately, an aggregate *p* is not quotable alone, and the dictionary-selection procedure states a policy for the class (R-15-036k). Whether the emitted call and global-address forms stay PC-relative or become **composition-time absolute** (position-fixed image, 36-bit dense physical space, `satp` Bare, so a call target is a composition-time constant and one entry serves every call site to a callee) is decided at the freeze from measurement, under the constraint that any absolute form remains one canonical 32-bit instruction and adds no CSR, no table, and no target-membership structure (R-15-036l). `Zcmt`'s `cm.jt`/`cm.jalt` and JVT are excluded independently of the purecap `C` encoding collision: no JVT CSR, runtime table read in the branch path, bespoke table authority rule, context-switch item, or `fence.t` flush-set candidate exists (R-15-036q).

**The one redundancy class the encoding cannot collect is sequences, and it is carried as a candidate rather than closed.** A dictionary entry is one instruction, so a prologue or epilogue idiom survives the encoding as a sequence. But the saves that make it up are stereotyped and therefore site-invariant, so a *k*-register save is already *k* slots and naming it collapses (*k* − 1) slots rather than (*k* − 1) instructions, which is half what the same instrument is worth upstream. `Zcmp`'s `cm.push`/`cm.pop` are refused on structure and not on that halving: their trap model is **restartable**, which keeps partial completion out of architectural state by putting a sequencer under it, and that is both a structure the absence contract would newly police and sequencing state in a front end whose decoder is stateless (R-15-036m). The one admissible form is **all-or-nothing with a single up-front check** on the stack capability against [`csp` − adj, `csp`) in place of *k* checks, which is the indexed load/store's argument again, *less* capability semantics on the path rather than more; whether it is carried at all is decided at the freeze by the same measurement that decides `bfext`/`bfins` (§3) and the call and global-address forms above, and the expectation is that it is dropped (R-15-036n).

**The general form of that class is refused an instrument here and given one in the compiler.** A dictionary index names one instruction and a multi-save names one idiom, so a recurring *region* is out of reach of both; the answer is **outlining** into a called helper and **tail merging** of shared epilogues, owned by the CHERI-CompCert backend under the ordinary secure-compilation obligation, intra-compartment, and profitable only for regions needing no frame of their own. It consumes no opcode space and adds no architectural state, flush-set member, admission-test case, or decoder state, so the amendment gate fails to arise rather than clearing (R-15-036o). It is nonetheless the one code-size lever that costs cycles: each region trades inline instructions for a call and a return, the return being an indirect branch with no return-address stack behind it, so it is measured on **two axes**, bytes removed and worst-case cycles added, and it is measured **first**, since it removes instances of the same stereotyped prologues the multi-save covers and every other candidate's corpus is the output of a backend that already outlines (R-15-036p).

**Two costs, booked.** §13's whole-image dead and duplication elimination (R-13-010a, R-13-010b) is partly **substitutive** with the encoding rather than additive and is measured composed, never multiplied; and it is ordered first, since a dictionary chosen against an unmerged image is chosen against the wrong histogram. The dictionary is a **permanent freeze-time commitment** of the same class as the capability format: a later change invalidates stored executable objects wholesale (R-15-036i).

| `Zicond` | branchless constant-time select (`czero.eqz/nez`); doubly load-bearing under static-only prediction. **Integers only**: the capability half is the conditional capability move (§4), the zero-then-OR idiom having no capability form | R-15-054, R-15-054a |

| `mtimecmp` | M-mode timer, programmed directly by the kernel | R-15-063 |

**`Zkt` + `Zvkt`** are adopted as the **leakage contract** rather than as instructions: the architectural statement that a listed instruction set runs in data-independent latency. That list is both the single leakage model constant-time verification is stated against and an RTL ⊑ Sail proof obligation (R-15-053). Two exclusions from it are named rather than left to a general clause, and both carry a discharged flow obligation rather than a self-declaration: `vfdiv`/`vfsqrt` on the operand side (R-15-082), and indexed and runtime-strided vector memory access on the address side (R-15-085a), the latter being the address-timing channel the banked SRAM keeps after the caches are deleted.

**AIA scope.** Only the *machine-level* interrupt files exist, and of those only the **pending array**. The supervisor and guest/VS machinery, and the delivery-enable, threshold, and top-pending-selection machinery, are dead Sail surface and are excluded; software reads pending bits with ordinary loads (R-15-065). The platform is MSI-only: no PLIC, no wired level interrupt on the die; the only non-MSI signals are the RoT's reset and watchdog-bite lines, which sit outside the interrupt model (R-15-066).

Each carries full Sail semantics and a recorded **re-pin obligation** where a standards track exists.

| Instruction / unit | Disposition | Re-pin target | Governing |
| --- | --- | --- | --- |
| `fence.t` | platform-custom; specified rather than invoked: enumerated flush set, mechanized completeness classification, padded constant cost | n/a | R-15-062 |
| Keccak-p[1600] | single vector instruction, fixed-latency permutation, **both 24- and 12-round** modes frozen; **vector-bearing cores only**, not the S-class RoT | `Zvknhk` / `vkeccak.vi` (RISC-V PQC TG, RVG-84) | R-15-056, R-15-056a, R-15-057, R-15-057a, R-15-059, R-15-059a |

| FEC units | LDPC and polar decoders only, fixed-geometry, deterministic iteration bounds, core-issued capability operands, no firmware | n/a | R-15-119 |
| CHERI dialect | frozen with the profile; **re-parameterized Concentrate at 64+1 bits**, algebra unchanged (§4.1) | **none**: the RVY re-pin is retired, not deferred, and the dialect is permanently bespoke | R-15-007, R-17-048a |
| Capability indexed load/store | `cld rd, cs1[rs2 << imm]` and its store form: bounds and permission check at base plus scaled index, **no intermediate capability materialized**; custom opcode space, scale immediate a composition-time parameter | **partial**: RVY's capability shift-and-add (`YSH1ADD`…`YSH4ADD`, `Zba`) covers the address-formation half only; the fused access is bespoke with the dialect, on R-15-007d's ground | R-15-007e, R-15-007f, R-15-007g |
| Bitfield extract/insert | `bfext rd, rs1, lsb, len` and `bfins rd, rs1, lsb, len`: multi-bit contiguous field read and deposit, where `Zbs` is single-bit only; custom opcode space, I-type field layout unchanged, specifiers and carriage decided by measurement at the freeze | **none**: no general bitfield proposal on the RISC-V track to re-pin to; the obligation opens if one ratifies | R-15-067a, R-15-067b, R-15-067c, R-15-067d |
| Masked register clear | `cclear h, mask`: clears the sixteen registers `mask` selects within the half `h` selects, each to untagged NULL, so two of them clear the merged file; custom opcode space, S-type field layout unchanged, no destination register named because the mask names the destinations | **`ZcheriSanitary`** (RISC-V, research-stage): nothing to re-pin to today, the obligation opening if it ratifies | R-15-069a, R-15-069b |

The Keccak unit has no Coq-native proof to import, so its fixed-permutation invariant is a fresh Sail proof disciplined against FIPS 202 and the NIST ACVP vectors as differential oracle; the `Zvbb`/`Zvbc` software path is retained as the portable route and the differential reference (R-15-058).

**Keccak re-pin target, recorded.** RVG-84 is `Zvknhk`, one instruction `vkeccak.vi`: vector-immediate multi-round Keccak-*p*[1600], **EGW 2048 / EGS 32 / SEW 64 only**, requiring `Zve64x` and mandating `Zvl128b`, with the immediate selecting 24 rounds (SHA-3/SHAKE) or 12 (TurboSHAKE/KangarooTwelve) and all other values illegal (R-15-057a). Three consequences are carried here rather than left to the re-pin. Data-independent execution latency is **mandatory in the extension itself**, so the `Zkt`/`Zvkt` keystone (R-15-053) is discharged architecturally for this instruction rather than imposed by this profile alone. The fork therefore freezes **both** round counts, so the re-pin is a substitution of encoding and not a widening of frozen semantics that would reopen the permutation lemma and the fixed-latency claim at ratification time (R-15-056a). And the 2048-bit element group is LMUL≤1 at the V-class VLEN=4096 but **LMUL=8 at the C-class VLEN=256**, one permutation consuming the whole architectural vector register file, so C-class Keccak figures are stated at that geometry (R-15-059a), a budget entry, not an admission one.

There is **no scalar Keccak instruction on the RISC-V standards track and none proposed.** RVG-84 is vector-only by construction, so the vectorless S-class and the RoT have nothing to adopt: their SHA-3/SHAKE stays plain 64-bit integer with `Zbb` rotations, which is both the constant-time answer on a fixed-latency core and the standards-aligned one (R-15-041, R-15-059). The matrix unit consumes int8/bf16 only: de-quantization and block-scale application are software on the M-class vector unit, and no block-scale register enters the frozen matrix ISA (R-15-117). Every byte the matrix unit moves is core-issued with explicit capability operands: no independent DMA mastership, no translation context, no firmware (R-15-118).

**The capability indexed load/store is the one row here admitted on code size, and it is the one row that is *less* capability semantics rather than more.** Its ground is bytes, not cycles: the offset-then-dereference sequence it replaces is already fused (§7), so the issue slot is collected and what remains is the 4 bytes of image and of fetch bandwidth a fused pair still occupies, against no I-cache, the 33–43% no-C penalty (R-15-036), and a composition-time SRAM capacity budget. That sequence is *every indexed dereference* on a machine whose only pointers are capabilities, so no second lever of this size exists (R-15-007e). What makes it admissible is the second half: `cincoffset` may produce a capability outside the representable region, a case the Sail model, `CJ-TAL-SOUND`, and `CJ-CERISE` each carry, and a single indexed access never constructs that intermediate, so the case **leaves** the dereference path rather than being discharged on it, and at §4.1's 256-byte exactness threshold it is the common case rather than the large-object one. It adds one Sail clause, one instruction-selection rule per backend (R-18-014a), one case each in `CJ-TAL-SOUND` and `CJ-CERISE`, and one fixed-latency entry in the timing-annotated model that keeps it on the `Zkt` list; it adds no architectural state, no flush-set member, no admission-test case, and no structure the absence contract must newly police (R-15-007f). The scale immediate is selected against the emitted mix by R-15-031a's discipline and frozen with the profile (R-15-007g).

**Its re-pin target is partial rather than absent, and the part that is missing is the part that matters.** RVY places a capability shift-and-add (`YSH1ADD`…`YSH4ADD`) in `Zba`, an extension this profile adopts, so the address-formation half of the sequence does have a standards-track form. It is not this instruction: it produces the intermediate capability and leaves the dereference to a following load or store, which is exactly the construction R-15-007f's admissibility argument turns on never performing, so adopting it would restore the representability case to the dereference path while still spending the four bytes of image a two-instruction sequence costs, which is the ground the instruction was admitted on. What a re-pin could recover is the address arithmetic; what stays bespoke with the dialect is the fusion of check-at-base-plus-index with the access, which is the whole of the instruction (R-15-007e, R-17-048a).

**The bitfield extract and insert is the second row admitted on code size, and the one row here whose carriage is still decided by a measurement.** `Zbs` is single-bit and RISC-V has no general bitfield operation, so a multi-bit field read lowers to shift-and-mask and a field write to mask-materialize, clear, shift, and merge: two instructions become one, and four to six become one (R-15-067a). What makes that a platform figure rather than a literature one is where the code comes from: the bit-aligned wire formats are parsed *and emitted* by Narcissus from one format description, which is what gives the insert form a first-class consumer here, and every MMIO register accessor on the machine is generated shift/mask code, which is the whole driver surface (R-15-067b). It clears the five-part test at fixed latency, so it joins the `Zkt` list with one entry in the timing-annotated model, and adds no architectural state, no flush-set member, no admission-test case, and no structure the absence contract must newly police; the short-dependent-ALU-chain fusion class is narrowed, not deleted, exactly as the capability pair above is (R-15-067c). **The carriage is conditional on measurement and that is the point:** the field-specifier form, the insert form, and the pair itself are re-derived at the freeze from actual generated output on the UPER RRC and IEI/TLV descriptors and the generated register accessors, and an immaterial measured delta drops the instruction rather than carrying it on the argument alone (R-15-067d).

**One further code-size candidate is named rather than left open, and it is not carried here because the same measurement decides it.** CHERIoT gives `csetbounds` a large immediate length, and the consumer for it here is not the upstream one: allocation is composition-time, so a narrowing the backend emits takes its length from a *type* rather than from a request (§4.1, R-15-007k), making the length a composition-time constant materialized immediately before the narrow. What that pair costs is halved by the encoding for the multi-save's reason: a site-invariant constant materialization is one dictionary entry reused at every site narrowing to that length, so the pair is already two slots and the immediate form collects one 16-bit slot rather than four bytes. It is therefore weighed in §11's single act beside `bfext`/`bfins`, the call and global-address forms, and the single-check multi-save, against the same outlined corpus and by the same rule, competing with them for the same custom opcode space; the expectation is that it is dropped (R-15-067e, R-15-036n).

**The third bespoke row is admitted on cycles rather than bytes, and that is what makes it a separate decision from the two above.** At a *partition* switch the register scrub is covered structurally, the restore being total over every register a partition can name (§5, R-07-015), which is why the register files sit outside the `fence.t` flush set. At a **compartment** switch nothing covers it: the switcher must leave the callee no register the caller did not pass and the caller no register the callee did not return, which on a merged file of 32 registers is some two dozen writes on the call path and again on the return path. The dictionary encoding does not answer this one, because it is a *byte* instrument: a stereotyped clear of a fixed register is site-invariant, so those writes are already two dozen dictionary slots and the image cost is collected before any instruction is added, while the issue cost is not: two dozen slots still issue two dozen times, on the platform's only inter-compartment path, in code §11 charges to every cross-compartment call. What `cclear` removes it removes from the **bound** and not from the mean, the clear being unconditional and its worst case therefore its every case. It clears the five-part test as the bitfield pair does, at a latency independent of operand values *and* of the mask's population, so it joins the `Zkt` list with one entry in the timing-annotated model; it mints no authority, being the one instruction on the machine that can only ever *destroy* authority, so monotonicity is trivial rather than argued; and it adds no architectural state, no flush-set member, no admission-test case, and no structure the absence contract must newly police, being a masked synchronous clear on the register file rather than sixteen write ports. ISAv9's deletion of `CClearRegs` is not inherited: it deleted the *split-file* variants a merged register file makes meaningless, which is a fact about the register file and not about the need (R-15-069a, R-15-069b).

Two parameters the pin leaves open are fixed here, the group being the CBO block `cbo.zero` allocates rather than an implementation-defined cache line, and the tags being reported **as stored** rather than as the revocation filter would return them, that filter having no base to index by. Authorized by the lattice element a tag-preserving capability load takes; fixed latency, dialect encoding, no custom opcode space | R-15-007q, R-08-007, R-15-203 |

**Excluded**

| Feature | Ground | Governing |
| --- | --- | --- |
| Interrupt-state sentries (`enabled`/`disabled`/`inherit`) | the one CHERIoT capability feature the profile declines: with asynchronous interrupt delivery deleted, the three sentry types collapse to one plain sealed entry | R-15-070 |
| CHERIoT compressed RV32 capability format | no second capability encoding forks the model, the RoT's scalar core included | R-15-005 |

**The forward/backward sentry split is ahead of the standards line's base, not adrift from it.** CHERIoT 1.0 ships the split for exactly R-15-071's reason, distinguishing a function pointer from a return address; RVY's base does not, keeping one sealing bit in the Capability Type field that replaces the object type and listing the split as a *future* CT value, with encoding room reserved rather than spent (`YSENTRY`'s `rs1` is held for a later sealing instruction taking an authorizing capability). The profile is therefore aligned with the line that has shipped it and ahead of the line that has not. What it declines beside it is CHERIoT's interrupt-state variants, excluded above because asynchronous interrupt delivery is deleted and not because the split is doubted (R-15-071, R-15-008, R-15-070).

**The load filter uses the CHERIoT non-MMU realization, not a page-table surrogate.** The attested devicetree gives a composition-fixed union of 64-byte-aligned revocable SRAM intervals. A dedicated sidecar bitmap carries one revocation bit per 8-byte capability granule in those intervals (`0` live, `1` revoked), so for intervals *I* its payload is exactly Σ|*I*|/64 bytes. The static memory plan charges the payload, ECC bits, and macro periphery against the SRAM capacity budget. The bitmap carries only the load-time live/revoked predicate; RVY `Svyrg`'s four-bit PTE protocol is not imported, and epoch, sweep, and quarantine state are not collapsed into this bit (R-08-005a, R-15-175).

**The tag clear is part of the load's own definition, not an effect layered onto it.** Every capability-width load carries the revoked case as one of its defined results: the value is written back with its validity tag cleared, at the one fixed latency §9 states. So the bank-side filter realizes an architectural result rather than acting outside the instruction that provoked it, and a load definition admitting only an unmodified tag or a trap could not express the check at all. With no colour in the format, this one clause is what both address-keyed cases rest on, the object case and the delegation case alike (R-08-005b, R-08-004a).

**The per-load check is architectural here and implementation-defined on the standards line, and the divergence is taken deliberately.** RVY carried a sub-extension naming whether loaded tags are actually checked (`Svucrglct`) and then dropped it, on the ground that software must assume the check might not happen, so naming it buys nothing. That ground does not carry here: R-08-005 makes the check architectural and fixed-latency **because containment latency is a proof obligation and a §11 schedule term**, the epoch advance being the containment constant and the sweep only reclamation behind it (R-08-006), so an implementation free to skip the check would not weaken an assumption but delete the term the schedule is built on. Same mechanism, opposite conclusion, and the profile's reason is specific to it: it is the position §4.1 takes on capability integrity as well, where there is no optional half either (R-08-005, R-08-005b, R-15-007a).

**Address keying is the whole mechanism, and it covers the subtree case too.** The one property ancestry keying held over address keying was revoking what one principal delegated without disturbing another principal's capabilities to the same object, and the profile buys it without a colour field because the authority model gives each *delegation* an address of its own: independently revocable cross-domain authority is a sealed capability bounded to a kernel-owned grant slot, so retiring it sets the bit for the slot's granule and not the object's (R-08-004a, R-08-004b). Nothing here is a format obligation: the grant table is kernel memory inside the covered union, and the filter that reads it is the one already specified above. This is what keeps §4.1's field table at 64 bits with no colour competing for them.

**Where the domain boundary does its argument validation is what declines the subset test.** `CTestSubset`, which RVY carries in its base ISA as `YSS`, answers whether one capability's bounds and permissions are contained in another's; upstream's first consumer is a garbage collector and there is none here, and its second, validating an argument at a domain boundary, is one this platform genuinely has. What that boundary validates is not containment. The switcher bounds a delegated buffer's *lifetime* through `store-local`, which the store path enforces (R-15-074), while its extent and rights are fixed by the IDL message type and the manifest's import/export tables over a composition-fixed distribution, so an edge admitting more than it should is a join failure at composition rather than a branch on the call path (R-05-124, R-05-096b). The residue is a **one-capability** question (long enough, and carrying the rights this operation needs) that `cgetlen` and `cgetperm` answer against a composition-time constant, and a capability that does not authorize its access faults there (R-15-007h) at no cost on the path that succeeds, where the tested form spends a forward conditional §11 charges to every cross-compartment call. The format decides the last of it: the permission half of the upstream test is bitwise over independent bits where §4.1's field is an enumerated lattice, so the instruction has no re-parameterized reading and would enter **bespoke**: its own Sail clause, its own comparator over the bounds encoding at 8 and 6 mantissa bits, and a stated agreement between the order it tests and the lattice's monotonicity. That is where R-15-007j's inheritance stops: it runs over *narrowed* fields, and the permission field is re-encoded rather than narrowed (R-15-007m).

**The sweep pair splits, and the split is between an instrument the profile has left itself needing and one the write path already covers.** Two reliefs the §8 sweep could have had are declined elsewhere: no revocation colour exists (§4 above), so the sweep is the only reclamation mechanism, and the CHERIoT-Ibex TBRE sweep engine is refused as an autonomous memory-touching walker (R-08-009), so the walk is software whose pass time is the quarantine a revoked granule waits out (R-08-007a). `cloadtags` is the third and the only free one: core-issued, so it touches memory only where an instruction says so, and one instruction per granule group where the loop otherwise spends a capability load and a tag test per granule. Its ground here is **issue rather than memory traffic**, which is a correction the tag plane forces: native tag bits sit in the array row beside the data and are read in parallel with it (R-15-203), so a tag-only read activates what a data read would and buys no bank cycle, and what it buys instead is the sweep's own quantum, a group's tags arriving as one operand rather than as N load-use latencies with no cache and no second issue slot behind. The saving is bounded and stated as bounded, the group size on an empty group and one instruction on a full one, and what it moves is a derived constant (R-08-007's completion latency, and the quarantine and background slot budget under it) rather than any security bound. It contends for no custom opcode space and no image budget, which is why it is not one of the instruments R-15-036n's single measured act weighs (R-15-007q).

**`CClearTags` is declined on the absence of a consumer, and the write path is why.** The sweep clears the tag of a capability whose base falls under a set revocation bit and leaves its neighbours in the same group standing, a per-granule conditional clear no group-wide unconditional one can express; the clear it performs is an ordinary non-capability store, since tag clearing on this machine is a property of the write path rather than an instruction, the same property under a vector store clearing every granule it overwrites (R-15-115a) and a non-capability DMA write clearing the granules it covers (R-15-183). That leaves *tags cleared where the data must survive*, and the zeroize discipline empties the case rather than narrowing it: where a region is reclaimed the data is dead and goes with the tags, at `cbo.zero`'s one fixed per-line latency over both planes' codewords (R-15-182), and leaving data standing while dropping its tags is the outcome eager zeroize and the disclosure half of Write-before-Read exist to prevent. It is R-15-061's decline in the other half of the same family, the difference being that the work is already done rather than absent (R-15-007r).

### 4.1 The capability format

**Read it as re-parameterized CHERI Concentrate, not as a bespoke format.** Same bounds algorithm, same capability algebra, same sentry and instruction semantics; different field widths. That distinction decides what is owed: the Cambridge monotonicity, provenance, and non-forgeability results are statements about the algebra and not the bit layout, so they are **inherited**, and what the change owes is a **representation-correctness proof** (encode/decode round-trip, field-extraction lemmas, derivation of base and top) over a re-parameterization of `sail-cheri-riscv`'s capability functions rather than a rewrite (R-15-007a). **The same reading decides the format's unstated cases**, which is why the table below qualifies only what deviates: an all-zeroes granule decodes as untagged NULL, the property eager zeroize and `cbo.zero`'s cleared tags rely on being able to read back (R-15-182, R-15-060); and every behaviour this section does not qualify is ISAv9's, inherited over the narrowed fields and discharged at these widths by that same proof (§11, R-15-007j).

| Field | Width | Note | Governing |
| --- | --- | --- | --- |
| address | 36 | the whole physical address space; stored uncompressed | R-15-002a |
| object type | 4 | the sealed-capability classes, known at freeze time | R-15-007 |
| permissions | 5 | **non-orthogonal**: an enumerated lattice, not independent bits | R-15-007b |
| exponent | 5 | as CHERI Concentrate | R-15-007 |
| base mantissa | 8 | the exactness threshold: bounds are byte-exact to 256 bytes | R-15-007c |
| top mantissa | 6 | high bits derived, as CHERI Concentrate derives them | R-15-007c |
| validity tag | 1 | outside the 64; one tag per 64-bit SRAM granule | R-15-203 |

**Eight consequences a curator should not have to re-derive.**

- **The algebra changes in exactly one place, and it is the permission encoding.** Five bits do not carry independent permission bits, so the admitted sets are enumerated at freeze time as a lattice with its join and meet, and monotonicity is restated over it: proved rather than inherited, bounded, and available only because the static task set makes the complete lattice known at freeze time. The enumeration is **total**: all 32 codepoints name an admitted set, the residue taking the bottom element, so the field has no illegal encoding to reject and its decode is a total function. It carries **no software-defined permission bits**: an SDP bit is uninterpreted by hardware, and what it would carry is carried better by the 4-bit object type, fixed at composition and machine-enforced where SDP is advisory; RVY mandates a 4-bit SDP field for all encodings and CHERIoT carries them, so this is a divergence rather than an omission, and the mandate binds RVY encodings that this dialect is permanently outside of. And it excludes **two** combinations at the lattice rather than downstream of it. It **separates `Permit_Seal` from `Permit_Unseal`**, admitting no set that holds both: the kernel mints grant slots and redeems them on two different paths (§4), minting is the authority to forge a delegation, and the redeem path is the one that runs on every cross-domain call. Sentries hold neither permission, `cjalr` unsealing the forward edge and sealing the return as instruction semantics. And it admits no set holding both `Permit_Store` and `Permit_Execute`, which is where CHERIoT's multi-rooted hierarchy lands here: W+X becomes a combination the format cannot denote, so R-14-002's absence of Store∧Execute is a finite check over 32 codepoints inside the decode rather than an enumeration of the composed initial distribution, true of every capability in every reachable state whatever its provenance. Disjoint roots would give the weaker form of the same property and would cost architectural state against a closed CSR table; the split of a core's partition-bounded root into an execute-side and a store-side capability is a corollary of the lattice, checked by the tool that composes the distribution. It bounds capabilities and not memory: the temporal case is closed by the absence of runtime code generation and the immutability of the image (R-14-004), not by the encoding (R-15-007b, R-15-007n, R-15-007o, R-15-007l, R-15-007p, R-15-068, R-08-004a, R-08-004c).
- **The object type is four bits wide, and the standards line has gone the other way.** RVY replaces the object type with a Capability Type field whose base keeps a single sealing bit, so the divergence runs in both directions and the profile is not the one behind: sixteen enforced sealed-capability classes here against sealed-or-not upstream, with the forward/backward sentry distinction §4 carries listed there as a future CT value. The width is spent because the deletion of the capability space makes it load-bearing: with no CNodes and no capability-address translation, sealing over a composition-fixed otype set is what supplies object typing at all, and the software classification RVY's mandatory 4-bit SDP field would carry advisorily is carried by these four bits enforced, a sealed capability being unusable rather than merely marked. The set is fixed at composition with no runtime type allocation, which is what makes the classes enforceable in the first place. Recorded as a divergence and not as a lag (R-15-007, R-07-002b, R-15-007n).
- **Bounds precision is spent, not bought.** The address is stored uncompressed, so 36 address bits inside 64 leave 28 for everything else and the mantissas land at 8 and 6: byte-exact to 256 bytes, rounding outward above that at a granularity of the length over 2^8, where a 128-bit format is exact to roughly 4 KiB. What makes it affordable here and would not make it affordable on a general-purpose machine is that allocation is composition-time, so the padding is computed by the static memory plan and only dynamic subobject narrowing carries the case at runtime (R-15-007c).
- **The rounding is closed at composition time, and no instruction computes it.** Upstream returns the representable alignment mask and the rounded length in `CRAM`/`CRRL` (RVY standardizes `YAMASK` into its base ISA) and asserts exactness with `CSetBoundsExact`; all three are addressed to a runtime allocator, and allocation here is composition-time. The residue R-15-007c books does not restore that consumer: a dynamically narrowed subobject's address is a composition-time slot base plus a composition-time offset plus a dynamic index times a composition-time stride, so its residue class modulo any composition-time alignment is known where the layout is decided even where the address is not known to the compartment holding it, and its length is its type. The static memory plan therefore lays every narrowable object out at its representable alignment and granule-quantized length and constrains a dynamic-length slice's split points to the enclosing array's representable granule, so **every `csetbounds` the backend emits is exactly representable by construction** and an outward-rounded narrow is a defect in the plan rather than a runtime event. Exactness matters here as authority and not as precision: an outward round hands the derived capability a 2^-8 fraction of the length beyond the subobject on each side, which a narrow splitting linear ownership hands to the recipient, so it is owed as an impossibility rather than as an assertion. `CSetBoundsExact`'s exception code is refused a second time on its own ground: an inexact narrow is *monotone*, so the trap would be this profile's only fault on a successful derivation, carrying the cause code and WCET term R-15-007h deletes everywhere else (R-15-007k, R-08-011).
- **The exactness threshold is what buys the indexed load/store in §3.** The intermediate `cincoffset` result falls outside the representable region far more often at 256-byte byte-exactness than it did at 128 bits, so the representability case the Sail model, `CJ-TAL-SOUND`, and `CJ-CERISE` each carry is now the common case on the indexed-dereference path rather than the large-object one. An instruction that never materializes the intermediate takes that case off the path where it is hottest, which is why the narrowing makes it worth more rather than less (R-15-007e, R-15-007f).
- **The budget is closed, and the revocation colour is not a claimant on it.** The table spends 64 bits exactly, and the one requirement that reads as though it wanted a sixty-fifth, subtree revocation, is discharged outside the format: a delegation that must be independently revocable is given an address of its own, a kernel-owned grant slot, so the address-keyed load filter in §4 decides the subtree case and no colour is stamped at derivation (R-08-004a, R-08-004b). A curator finding a future claimant on these bits should read this as the standing answer: the format does not grow, and a property that seems to need a field is first tested against whether the authority model can give it an address.
- **Capability integrity reduces to one check, and it is a bounds check.** Integrity splits three ways upstream: reserved-field legality, a legal-permissions invariant for tagged capabilities, and malformed bounds. The first is vacuous here, the table spending all 64 bits with no reserved field to police. The second is structural rather than checked, the permission enumeration being total where a one-bit-per-permission field validates 90 encodings of 512. The third is real and is the one the narrowing creates: which exponent and mantissa triples derive a top below their base is a property of the bounds algorithm at 8 and 6 bits, so R-15-007a's representation-correctness proof states decode as a **total function over the 19-bit bounds encoding** and characterizes that set at these widths rather than inheriting it. A malformed capability holds and faults at its next dereference rather than trapping where it was constructed, which is where R-15-007h already puts every failed derivation, so it adds no cause code and no `mtval` case. **There is no optional half**: fault behaviour is a proof obligation and a §11 schedule term, which is the ground §4 gives for making the per-load tag check architectural too (R-15-007a, R-15-007h, R-08-005).
- **The width is permanent.** Every capability in the immutable image and every sealed blob is stored in this format, so a later width change invalidates stored authority wholesale rather than costing a recompile. The margin is argued once, against the SRAM capacity bound rather than against an expectation: the roster tops out well inside 64 GB and there is no DRAM growth axis to plan for (R-15-002a, R-15-007d). Its corollary is that the physical address map must be **dense**, a constraint on the attested devicetree and the binding map rather than a discovery at composition (R-15-002b).

The `senvcfg` half is absent above with the rest of the S-mode bank (R-15-003); the `menvcfg` half is not a bit this profile clears, and not a bit deleted incidentally along with its register in §5.3: it has no allocation here at all. **No CSR field in §5.1, §5.2, or §5.3 carries a value that turns capability enforcement off**: the platform is purecap-only with no capability-degraded state (R-15-001, R-18-002), CHERI is the sole memory-protection mechanism (R-15-075), and the disable-side switch is refused by read-only `misa` (§1, R-15-052). §5.3's `menvcfg` → **deletion** therefore deletes a register whose bits gate a mode that does not exist, and nothing further; there is no CHERI enable inside it to delete along with it.

**A trap taken while the trap path is live is fail-stop, and that is what declines the second saved-PC bank.** The MIPS-lineage CHERI ISAs carried `ErrorEPCC` beside `EPCC`; RISC-V never carried `ErrorEPC`, and asks the question later and twice, as `Smrnmi`'s `mnepc` bank (so a resumable NMI landing in a handler does not clobber `mepc`) and as `Smdbltrp`'s `mstatus.MDT` bit (so a trap taken while one is being handled is a critical error rather than a re-entry). The register-adding answer has no consumer here, because a saved program counter exists to be returned to and nothing returns: the kernel is entered for exactly two reasons and both of them *are* the trap path (R-07-021), so a trap taken between that entry and the `mret` that leaves it is a **synchronous fault in kernel code**, refuting the kernel proof rather than presenting a recovery arm, and its disposition is the crash-only fail-stop and supervised restart (R-12-001, R-16-005). Nor does the asynchronous half arise: `ErrorEPC` and `mnepc` bank reset, NMI, machine check, and cache error, and every one of those is already off the trap path, the platform being MSI-only with reset and watchdog bite outside the interrupt model (R-15-066), an uncorrectable ECC or tag-integrity event being a fail-stop sentinel event rather than a trap (R-15-204), and the slot-boundary timer being suppressed by the trap path itself and not re-arming until the handler reprograms `mtimecmp` (R-07-040). **What the profile takes instead is `Smdbltrp`'s disposition without its CSR field** (R-15-073c): the second trap does not vector to `MTCC` and does not write `MEPCC`, `mcause`, or `mtval`, so the first fault's report survives intact for the development-state Debug Module to read, which is the post-mortem the bank was buying, at an omitted write rather than a capability-width register the total restore would have to name (R-07-015). The condition is one bit of trap-path state with no software-visible field, so `mstatus` gains no `MDT` and this table is unchanged by it.

**Two exclusions are recorded with their accepted costs rather than as free wins.** Vector-FP-without-scalar-FP is a deliberate, Sail-modeled **fork of standard RVV**, admissible only because the platform curates its own profile and formal model; its cost is a soft-float-register calling convention, accepted (R-15-040). And dropping PMP forgoes the one **CHERI-disjoint failure domain** PMP uniquely offered: the hedge becomes CHERI's own formal verification, and the resulting concentration is booked in §17 as the RTL ⊑ Sail arrow plus a Coq-native restatement of reachable-capability monotonicity over the CHERI-RISC-V Sail model (R-15-076). Neither is a deletion the profile gets for nothing, and a curator reading only the exclusion table would miss both.

**A third fork is recorded with no cost to book, which is the reason to record it.** `vstart`-free RVV is a Sail-modeled fork on the same ground as the first, standard RVV defining `vstart` as mandatory, but where the scalar-FP fork bought its deletion with a calling convention this one buys nothing: no ABI names `vstart`, no compiler emits a write to it, and the residue is hand-written RVV assembly setting an element base, which admission rejects as an undefined instruction rather than miscompiling (R-15-040a). A curator should read the absence of an accepted cost here as a claim to check, not as a row that was written carelessly.

**One exclusion runs against the standards line, and what separates them is a constraint rather than a judgment.** RVY integrates pointer masking because RVA23 requires it; R-15-043 deletes `Ssnpm`/`Smnpm` outright, obviated by CHERI with no top-byte-ignore mechanism anywhere on the machine. The divergence is **entirely a profile-compatibility artifact**: RVY must land inside a ratified application profile and carry what that profile mandates, where this document *is* the application profile, curated against one composed image. Nothing in the row turns on which mechanism is better, so a later reader should read the standards line's adoption as an obligation the profile does not have rather than as pressure on the exclusion (R-15-043, R-15-001, R-15-012).

## 8. Core classes

One shared scalar front end (CVA6-class, modified to static-only prediction) across all classes, so kernel-path WCET is a single analysis (R-15-112). Counts are composition parameters, not architecture (R-15-113).

| Class | Datapath | Notes |
| --- | --- | --- |
| **C** | scalar + RVV, **VLEN=256** | control and application |
| **V** | long vector, **VLEN=4096**, 8 lanes | includes a radio-pinned pair; vector, **not** fixed-function graphics and not SIMT: no rasterizer, texture units, ROPs, command processor, or hardware warp scheduler (R-15-115) |
| **M** | systolic GEMM + **VLEN=1024** + software-managed scratchpad | matrix extension admitted only on an 8–10× sustained dense-GEMM margin over the same GEMM as RVV on its own VLEN=1024 unit (R-15-116) |
| **S** | scalar sentinel | vectorless; hashes SHA-3/SHAKE in plain 64-bit integer with `Zbb` rotations (R-15-041) |
| **RoT** | OpenTitan-class scalar RV64+CHERI, own clock/power island | no V/M; main-die purecap capability format, **not** CHERIoT's encoding (R-15-005, R-15-113) |

Capability checks land on scalar-issued vector/matrix memory operations, per-element for gather/scatter; vector data carries no tags, keeping CHERI a single-front-end problem (R-15-115). A vector store therefore **clears the capability tag of every granule it overwrites**, partial-granule writes included: *vector data carries no tags* says what a vector store writes, not what happens to the tag of what it replaces, and a stale tag left standing over overwritten data is a forgery primitive rather than a residue (R-15-115a).

Only an **active** element raises a capability exception, and the check is nonetheless run for every element. §9's mask-independence contract forbids returning the cycles or the memory accesses of masked-off elements, so where it applies those accesses happen and their checks happen with them, at the cost an active element's check takes, with the result discarded rather than raised; a masked-off element whose check fails takes the bank cycle its access would have taken as a padded access presenting no address, keeping an unauthorized address off the fabric at no timing cost, since an on-list access's bank sequence is a function of element width and a granule-aligned base alone. *Check every element, fault only on the active ones* is not a compromise between a security contract and a timing one but the only realization of both: skipping the masked-off check hands back the cycles §9 holds and leaks the mask through timing, and raising its fault leaks the mask through the trap (R-15-115b, R-15-085).

## 10. Debug

The RISC-V Debug Module exists in silicon but is **lifecycle-fused at the hardware level**, never merely software-gated: in the production lifecycle state the RoT's OTP fuse holds its clock and reset gated off and its fabric port electrically quiesced. *No DM transaction reaches the fabric in the production state* is a stated RTL ⊑ Sail obligation, so the Sail model carries the gate rather than a model of the debugger (R-15-078). In development and RMA states, DM entry is an RoT challenge-response (ML-DSA-signed, serial-bound), the key hierarchy diversifies by lifecycle state, and moving a fielded device to a debuggable state crypto-erases first; trace rides the same fuse (R-15-079).

**What the fuse refuses is a capability-debug surface, and that is worth stating with the fuse.** The standards line spends real effort making an external debugger work against capability state: CHERI mode on debug entry, a `dpcc`, a `drootcsel` root-selection register, capability-width abstract commands, and a debug specification split out into its own document. None of it appears here, and the profile's answer is orthogonal to it rather than behind it: the surface is deleted at *reachability* rather than fitted to capabilities, so in the production state there is no DM transaction for a capability-aware abstract command to ride and no root-selection register to add against §5's closed table, and in the development and RMA states the DM is reached only through the challenge-response above, on a part crypto-erased on the way in if it was ever fielded. A curator comparing the two should read the absence as a refusal and not as debug work the profile is missing (R-15-078, R-15-079).

## 11. Freeze and re-pin obligations

**The freeze is two acts** (R-15-014a). Several decisions in this document are re-derived from measurement against generated output, and that output does not exist before a backend and a composed image do, so the freeze splits: the **provisional freeze** fixes everything not so conditioned and is the schedule root R-18-003a names, while the **final freeze** is the act "frozen with the proof" refers to. Every *decided at the freeze from measurement* in this document is decided at the second act; everything else is decided at the first. The delta between them is closed:

| --- | --- |
| Realized dictionary size, entry selection, and the site-varying-operand policy | R-15-036i, R-15-036k |
| Bundle, header, and slot widths (§1.1's reference instantiation), the one structural item, allocating no opcode and changing no semantics | R-15-036a |

| Frozen fusion-set membership | R-15-031a |

Each row has a **declining provisional value** (no admission, PC-relative forms, an unselected dictionary), so the provisional profile is a complete compilation target rather than a partial one, and an item admitted at the final freeze costs one selection pattern, one Sail clause, and a dictionary regeneration. A change outside the table is an amendment and reruns the review gate (R-18-034). The gating artifacts of the second act are R-18-003c's: the CHERI-CompCert functional core with outlining landed, a composed image taken after the §10 and §13 stripping levers, and the corpora R-15-067d names. Permanence attaches to the second act alone, no image encoded under the provisional dictionary being deployed or stored, which is what keeps R-15-036i's wholesale-invalidation cost and R-15-007d's width commitment where the proof is.

Two components carry standing re-pin obligations, and each re-pins to a ratified base rather than to a private snapshot:

- **Matrix extension** → a ratified AME/IME-lineage extension when one supersedes it (R-15-009)
- **Keccak** → RVG-84 when the RISC-V PQC Task Group's instruction ratifies (R-15-057)

**CHERI carries none, and its absence is a decision rather than an omission.** Narrowing the capability format to 64+1 bits (§4.1) retires the re-pin to the ratified RVY base outright: the dialect is permanently bespoke. What that spends is oracles rather than a badge, `sail-cheri-riscv` becoming a model this platform parameterizes and maintains rather than one it inherits, and the CHERI half of the differential-testing surface degrading in **two terms rather than one**: the **algebraic** oracles (bounds encode/decode, the representable-region predicates, monotonicity) degrade in proportion to the parameterization, while the **instruction-level** oracles (Spike, QEMU, the CHERI test suites) do so only while they sit on the ISAv8/v9 lineage this format re-parameterizes and closer to all at once as they track RVY, which now shares with that lineage neither mnemonics, nor encoding space, nor CSR names, nor sealing's carriage, nor the format's name. The proportional term is what makes a short, bounded deviation list affordable where a clean sheet is not; the wholesale term is why the count of amendments to the frozen dialect is itself a quantity to keep small. The loss is booked in §17 with its compensating obligations named (R-17-048a). The one *partial* target §3 records (RVY's capability shift-and-add against the indexed load/store's address formation) is not a standing obligation of this kind: it covers half a sequence and not the instruction, so there is nothing a re-pin would exchange.

**What is retired is a parameterization, not a mechanism, and the standard's own structure is why that distinction has to be drawn.** RVY separates the base ISA (`RV64Y`) from the capability encoding format that completes it (`RV64LYA`, parameterized by mantissa width, exponent width, and maximum exponent, and named under an `_L<params>` scheme), and states that every RVY base ISA requires an encoding format to complete the specification. Alternative parameterizations are therefore a first-class part of that standard rather than a departure from it, and §4.1's format is a different filling of the same slot rather than a different kind of object, which is the same fact R-15-007a leans on in calling the change a re-parameterization and not a rewrite. What retires the re-pin is the widths and not the slot: a 36-bit address is not an RVY address size and 8- and 6-bit mantissas fall outside anything the standard will ratify, so the mechanism offers a place to *name* this format and no route to a ratified one. Two consequences follow, and neither disturbs the decision R-15-007 records. The retirement is declining a parameterization the standard would ratify rather than declining a mechanism the standard does not offer, so the ground stated for it is the field widths and nothing about fork-versus-adopt. And the oracle cost above is unchanged by the slot's existence, because the oracles implement `RV64LYA`'s parameters rather than the naming scheme: a format nameable in that scheme and executable by nothing still degrades in the two terms already booked (R-15-007, R-17-048a).

**Retiring the re-pin does not release the profile from the pin, and silence resolves to ISAv9.** Where this document is silent on the *behaviour* of a construct it carries, ISAv9's semantics govern and the deviations recorded here are exhaustive: an unstated behaviour is a lookup against the pin rather than implementer latitude, and one found later to deviate without appearing in the list is a defect in the list rather than a divergence anyone may keep. The clause runs over semantics and **not** over membership, so nothing enters the profile by inheritance: what exists is decided by §2's extension set, §5's closed CSR table, §6's exclusions by name, and R-15-014's trap on every unallocated encoding, and an ISAv9 instruction this document does not name is absent until admitted on a stated ground. That is the difference between a curated profile and a subtractive one, and it is why "everything ISAv9 has, minus the exclusions" is not what this clause says. The inheritance is version-pinned rather than tracking: ISAv10 is not a source and neither is the retired RVY line (R-15-007j, R-17-048a).

A re-pin is an amendment to the profile and therefore reruns the review gate (R-18-034).
