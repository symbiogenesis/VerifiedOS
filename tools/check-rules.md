# The Checker's Rule Registry

*The enumerated reach of [check.py](check.py): one row per check the tool carries, stating what passing means and on what ground. [proofs](../proofs/) are gated separately by [proof-gate.py](proof-gate.py), whose whole contract is one sentence: every shipped constant's assumption set equals the declared set R-05-164 reads from the register, which is empty today.*

## Why this document exists

The checker is untrusted machinery: a defect in it costs reviewer attention, never soundness, so it is not verified and never will be. What the review gate is owed instead is a readable account of the tool's reach, so that the gate can price what is machine-held and what is not without reading the source. This table is that account. Each rule's **Passing means** column is the claim the run's `ok` line asserts; the **Ground** column names the requirement or discipline the check serves.

The closure is the register's own conferral shape applied to the tool: this registry and the code are two artifacts, and `check.py`'s meta group holds them in agreement in both directions on every run, failing on a registered rule no check carries and on a check carrying no registered rule. What no closure can decide is whether a registered claim is the *right* claim; that residue is a person's, exactly as it is for every enumeration the tool checks.

A second instrument stands behind the rows themselves. [check-selftest.py](check-selftest.py) carries one seeded defect per rule, mutates a sandbox built from the working tree so that the rule must report, and fails on the rule that reads the defect and says nothing. It is held against this table in both directions too, so a row added here without a case is a finding, and it is what keeps a row from being a claim about a check that has stopped deciding anything. Passing it means each rule *bites*, which is a weaker thing than each rule being right and a stronger thing than the run being green.

## What the registry is not

It is not a specification of the checks' algorithms, which stay in the source where they can be read beside their data, and it is not a promise of semantic coverage: a rule can hold while the sentence it guards states the wrong thing, which is the residue the register's own gate discussion names. A rule whose claim has drifted from what its check decides is a defect of this table, repaired by editing the row, never by widening the claim to fit.

## What a passing run does not decide

The gate should price this table by what its rules reach, and the reach has a boundary worth stating rather than leaving to be discovered. A rule decides a property of a set the tool locates in a document, so the honest question about any row is not only whether the property holds but whether the set is the intended one, and there are four answers. Every rule the registry carries is named under exactly one of them below, because a class list that stopped growing as rules landed would be this document's own version of the defect it describes.

Where the set is found by **name**, staleness is caught outright: an identifier, a bookmark, a link, a section number, or a required artifact either resolves against the thing declaring it or is a finding, in both directions, which is what K-01 through K-17, K-18 through K-22, K-42 through K-44, K-48 and K-49, K-50, K-62, K-63, K-66, K-70, K-72, K-74, K-76, K-77, K-80, and K-81 are. K-77 is that same both-directions shape run once per enumeration over one pair of artifacts, the freeze contract's enumerations against the analyzer implementing them, and it is worth naming apart for what the further ones buy: a rule holding the CI predicates alone would report green while the instrument carried three region classes and two report blocks, those two enumerations constraining each other not at all. Its two relations sit here for the same reason the memberships do, each end naming the other by an identifier that either resolves or is a finding; what separates them is that a relation is quantified over both rosters at once, so an identifier neither side declares is reached rather than walked past. K-80 is the one of them whose resolution is against the **index** rather than the filesystem, and the difference is the claim: the page says what this repository redistributes, and a licence file sitting untracked beside the code it governs is not redistributed by it, so *present* is the wrong test and *carried* is the right one. K-81 is that pairing over an enumeration git holds rather than one a document declares: every gitlink the index carries resolves against a row of the licence record and back, and the commit each of them states is then the figure held across the pair, so a pin advanced without its row is a name that has stopped answering rather than a count that has stopped adding up. Its second reach is the wider one and belongs to this class for the same reason, every further site that restates a pin resolving against the record's row for it, which is what separates a record that agrees with the index from a repository saying one thing about an edition in one place and another elsewhere. Its two floors are members of K-47's, one under each side of the pair, and they are floors of two different kinds: the record's rows are located by heading and column name, so theirs catches a section retitled away, while the restating sites are located by pattern, so theirs is the ordinary one this class does not otherwise need. The conferral rules sit here rather than beside the pattern ones because each holds a citation: K-18 through K-22 ask that a status name the entry conferring it, the seam collecting it, or the enumeration that gathers it, so a conferral whose collector has been retitled away is a finding rather than a shortfall. K-63 is the same shape reaching outside the document corpus, every requirement id the curated model cites having to name a live entry, and K-66, K-70, K-72 and K-76 are it in both directions at once, over the profile's exclusion rows against the model's decode surface, over the freeze delta's items against the instrument accounting for them, over the corpus's emitted words against the section enumerating them, and over the absence contract's claimed structures against the record binding each to a build. K-76 reaches a third artifact past its two, the configuration package the record's settings are stated at, which is what separates a record that agrees with the contract from one that also describes the build in hand. K-62 is worth naming apart from the rest of them, because its set is the one a *figure* was standing in for: the section count is arithmetic over the register and so reports nothing about the prose, and the two section sets held against each other are what make the count's sentence mean what it says. K-74 is worth naming apart for the opposite reason: its set is the one a *reading* was standing in for, the coverage matrix's own claim that a cell's mode reports how its cited requirements carry the pair, of which exactly one mode has a name to resolve against, so the rule reaches the residual column and nothing else the sentence covers. Its vocabulary is located by pattern rather than named, and its floor is a member of K-47's accordingly. Where the set is a **computed value**, it is recomputed rather than trusted, which is what K-24 through K-37, K-51, K-54, K-57, K-60, K-61, K-65, K-67, K-69, K-71, K-75, and K-79 are: K-51 by assembling every corpus program rather than by reading a figure about it, K-54 by dividing two fields the register owns rather than by trusting a ratio somebody wrote down beside them, K-57 by compounding the constraint arithmetic rather than by reading the candidate set the document states it as, K-79 by reading the frozen capability format out of the two Sail files that fix it and holding every restatement and both packings against that rather than against each other, so that the claim four artifacts rest on, that the fields spend the capability's bits exactly and leave no reserved field, is arithmetic over the widths and not a sentence, K-60 by holding all four sites that write a class's vector geometry against the one composed value rather than against each other, and every stated core count against the one composed roster that could realize it, and K-61 by re-digesting both sides of every pair rather than by trusting that a recorded reading still describes them. Where the set is found by **pattern**, a regex or a literal that locates content rather than naming it, the pattern does not fail when the document moves under it; it matches less. K-46, K-47, and K-55 floor the case where it matches nothing at all, which is the common one, because deletions and renumberings are common and an empty set satisfies every property vacuously; K-46 does it by requiring that every computed quantity be claimed somewhere, so the prose disagrees loudly, K-47 states the floor directly for the sets no figure counts, and K-55 states it for the two-class figures, where the half the register owns is floored on its owner and the half the register deliberately withholds is floored on the withholding rather than on a value. K-45 is the same floor applied to the tool's own carve-outs, and K-23, K-56, K-58, K-59, K-68, K-73 and K-78 are ordinary pattern rules whose own floors are members of K-47's, K-73 carrying a second guard beside that floor because the enumeration it reads is one sentence: a form it cannot parse is a finding, so the rule cannot quietly fall to reading no states and then report the agreement of two empty sets. K-78 is worth naming apart from the rest of them because only half of it is located by pattern: which configurations it decides about is computed, the composed hart being an index into a roster, and what it decides about them is the pattern's, the model's own minimum-vector-length rungs and config-gated vector flags. A ladder that stopped matching would leave every geometry below no rungs at all, which is the vacuous pass the floor exists to catch, and the flags are the half that fails the other way, a registry row respelled leaving a switched-on extension unread. K-84 is that same split with its floor in a third place: which citations it decides about is the pattern's, a rule id written in bold, and what it decides about each is by name against this registry, so a document that stopped bolding the rules it relies on would leave the rule resolving nothing while every gate stayed green. Its floor is inside the rule rather than a member of K-47's, because the meta group reports after the floors group and so has no count to hand it, which is the same reason the two rules beside it are fail-closed at each site instead. K-23 is the one to read first, because its pattern is a vocabulary alternation and it is therefore the worked example of the hazard this section closes on: it catches the candidates a judgment word names, so a word dropped from that alternation narrows the agenda without emptying it.

Where the set is **total**, there is nothing to locate and therefore nothing that can quietly narrow: the tool walks an enumeration it holds itself, the git index or the registry or a document's own rows, rather than one some sentence points it at, so the only way for a member to escape is for it to leave the repository. That is what K-00, K-38, K-39, K-40, K-41, K-52 and K-53 are: the registry against the code in both directions, every table row against the header it sits under, every tracked file against the punctuation and encoding rules, and every tracked file against the licence mark its kind carries, with every kind either given a comment syntax or refused by name. This class is worth naming apart from the other three because it is the one the closing paragraph's hazard does not reach: a green run here is evidence about the whole subject, where a green run over a located set is evidence about the part the name, the computation, or the pattern still finds.

K-59 is worth one further sentence, because its set is narrower than its subject and deliberately so. The prose names an entry of *this* document by its subject rather than by its heading, the FGMT entry and the tagged-architecture entry naming headings that carry neither word, so the rule takes only the references a sentence attributes to another document, where the reader cannot see the target and an edit made wholly inside that other file can retitle or merge the entry away. A name written as a rationale or an argument rather than as an entry claims no heading, and the rule does not read it.

What no rule here reaches is a pattern whose yield falls **without reaching zero**. Drop one term from a vocabulary alternation and the agenda quietly narrows, the remaining candidates are still checked, and the run is still green. [check-selftest.py](check-selftest.py) takes the part of that a machine can have, by seeding each rule a defect it must report, which catches the rule that has stopped deciding anything even while its set stays populated; what it cannot catch is the rule that still decides its seeded case and has narrowed around every other one. A reference that still resolves while its referent has changed meaning is that same semantic residue seen from the other side, and K-61 takes the half of it a machine can have. It cannot read a paragraph and decide whether it still supports the entry extracted from it, which is a reading; what it decides is whether either side has moved since the two were last read together, which is the condition under which the question arises at all. So the residue narrows rather than closing, and what is left of it is the pair whose two sides both stand as they were recorded and whose agreement was misjudged at the moment it was recorded. That and the narrowing pattern above are a person's to catch, and a run reporting every rule green is evidence about the classes above and not about these.
